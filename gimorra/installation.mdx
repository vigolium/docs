## What the installer does

One script, five steps, no surprises:

1. Detects the platform. Gimorra supports macOS and Linux, on arm64 or x64.
2. Finds the current release and downloads it. It checks the SHA-256 checksum, and it also checks the release signature when the host's `openssl` supports Ed25519. If a checksum is missing or wrong, the install stops.
3. Installs `gimorra` in `~/.local/bin` by default, and adds that directory to `PATH` in your shell profile.
4. Installs the Vigolium scan engine version that this Gimorra release is tested with, unless Vigolium is already installed.
5. Runs `gimorra setup --yes` to finish setting up the host and to list anything left for you to do.

## Installer options

Pass options after `bash -s --`:

```bash
curl -fsSL <your install URL> | bash -s -- --for audit
```

| Option | What it does |
|---|---|
| `--for scan` | Sets up the host for live scans. This is the default. |
| `--for audit` | Sets up the host for source-code audits only. It installs the audit tools and skips the scan engine. |
| `--for browser` | Also installs the browser that browser-driven agents use. |
| `--for all` | Installs everything above. |
| `--path <dir>` | The source tree that `--for audit` sets up language servers for. |
| `--prefetch` | Also downloads the files a run would otherwise download the first time it needs them. |
| `--skip-engine` | Skips installing the Vigolium engine. |
| `--version <v>` | Installs a specific release instead of the latest one. |

## Where to run it

Gimorra runs its tools as your user, on the machine where you start it. Give it a VM, a container or a box you can throw away, not the laptop that holds your keys.

<Tip>
  In a cloud coding sandbox such as Claude Code on the web, put the install command in the environment's setup script. In auto mode, the agent is not allowed to pipe a downloaded script into `bash` during a session.
</Tip>
