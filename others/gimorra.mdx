**Gimorra** is the autonomous offensive-security platform within Vigolium — *hunts while you sleep*.

Point it at an **authorized** target with a goal and a scope, and it runs the whole engagement on its own: **recon → scan → propose a PoC → deterministically prove it → report**, with a human in the loop only where blast radius actually requires one.

Vigolium is the scan engine underneath it. Gimorra is the operator above it.

## Autonomy bought with guardrails, not supervision

Autonomous offense is usually gated by a human on every action, because a mistake reaches out and touches something it shouldn't. Gimorra takes the opposite route: make the run **incapable** of harming the target, so supervision becomes a dial rather than a per-action crutch.

<Columns cols={3}>
  <Card title="Deterministic validator" icon="circle-check">
    Ordinary code — not the model — re-proves every finding with the least-invasive action that settles it. The agent proposes; code disposes. **No self-certified bugs.**
  </Card>
  <Card title="Auto-cleanup & kill switch" icon="power-off">
    Anything a run changes is reverted, and one command stops the engagement: queued work becomes unclaimable and no further proof is accepted.
  </Card>
  <Card title="Scope guard" icon="shield-halved">
    Deny-wins, and ambiguity blocks. Evaluated on every single tool call, before anything else gets a say.
  </Card>
</Columns>

None of the three depends on the agent, the model, or the network stack. **If the model is prompt-injected, they still hold** — that property is the whole point.

<Warning>
  Gimorra only operates against targets you are authorized to test. **No authorization artifact, no active operation** — enforced in code, not policy.
</Warning>

## What you can point it at

| You give it | What comes back |
|---|---|
| A URL, host, domain, IP or CIDR | A scoped, authorized engagement: the target mapped, tested, and the real findings proven |
| A plain-English brief | The same, steered at what you actually asked for — "focus on IDOR and broken access control" |
| An API spec or a captured session | The documented operation set turned into testable surface before anything is sent |
| A source repository or a shipped app bundle | A source-code audit, alongside the live target or on its own |
| A whole bug-bounty scope document | Every in-scope asset worked as one engagement |

One dial controls how far it goes — from fully passive to aggressive — and nothing else needs tuning to get a first result.

## How it relates to the rest of Vigolium

| | What it is | Reach for it when |
|---|---|---|
| [**Native scan**](/native-scan/how-it-works) | Deterministic, module-based scanning | You want broad, repeatable coverage, fast |

| **Gimorra** | An autonomous agent running the whole engagement | You want the engagement itself handled, start to finish |

<Note>
  Gimorra runs the tools directly on the machine it is started on, so the boundary around a run is the environment you start it in. An all-in-one container image is the recommended way to give it one.
</Note>
