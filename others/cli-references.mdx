A curated tour of the most common `vigolium` invocations, grouped by command. For the full flag list of any command, run `vigolium <command> --help`. For the same examples in your terminal, run `vigolium --full-example`.

## Top-Level Commands

```bash
vigolium --help              # All available commands and global flags
vigolium <command> --help    # Flags and help for a specific command
vigolium --full-example      # Curated tour of all common usage
vigolium version             # Build and version info
```

### Exit codes

Since v0.4.5 the exit status is a **table**, not two values:

| Code | Meaning |
|-----:|---------|
| `0` | Success (or `--soft-fail` forced it) |
| `1` | Error — the command failed to do its job. `error.code` says how (`source_missing`, `export_failed`, `no_targets_in_scope`, `no_targets_reachable`, …) |
| `2` | Usage error — bad flag, bad value, rejected combination, a search that matched nothing (`module enable`), or a mutation that needed `--force` with no terminal to ask. `error.code: "usage_error"`, except a scan whose `--ext` extension failed to load before any request: `extension_load_failed` |
| `3` | `fuzz --fail-on-match` (or `kit secret-scan --fail-on-match` / `kit jwt-crack --fail-on-crack`) matched |
| `4` | A `--fail-on <severity>` (or `scan diff --fail-on-new <severity>`) gate tripped |
| `5` | **Incomplete** — the work ran but did not finish. `error.code` is `timed_out`, `budget_exhausted` or `partial` |

<Warning>
  **`3`, `4` and `5` are not failures.** The command ran, wrote its output, and is telling you what it found — the opposite outcome from `1`, where it never got that far. Before v0.4.5 these all returned `1`, so a CI job could not tell "the scanner crashed" from "the scanner worked and found a critical". Branch on them separately: treating every non-zero as breakage either ignores real outages or reports every finding as one.
</Warning>

<Note>
  **`5` is the agent-run outcome (v0.5.3).** `agent autopilot` / `swarm` / `audit` exit `5` when the run stopped short of finishing: a `--max-duration` stop, a `--max-commands` / `--token-budget` / `--max-cost-usd` budget exhausted, or an audit in which some drivers failed. `agent query` and `agent triage` exit `5` past `--max-duration`. The run still finalized — summary, triage and transcript were all written — so read the results rather than retrying blind.

  A **native** scan that is merely partial still exits `0`; read `completeness` and `stop_reason` on the scan document instead. `scan wait --fail-on-partial` is the opt-in that turns that into a `5`.
</Note>

`--fail-on <info|suspect|low|medium|high|critical>` works on `scan`, `scan-url`, `scan-request`, and `run`, and **output is always written first** — the gate only changes the exit code. Under `-P/--parallel` the gate is evaluated per child, and the parent batch fails only when every target fails.

The global `--soft-fail` flag forces an exit code of `0` even when a command fails (the error is still printed to stderr), and overrides `--fail-on`. It keeps a failing `vigolium` call from interrupting the wrapping script or CI pipeline:

```bash
vigolium scan -t https://example.com --soft-fail
```

### Global flags

These work on every command (run `vigolium --help` for the authoritative list):

| Flag | What it does |
|---|---|
| `-j, --json` | Machine-readable JSON for agent / programmatic use (compact bodies; pairs with `--fields` / `--compact` / `--full-body`). Every command emits the [same envelope](/getting-started/cheat-sheet#the-json-envelope) |
| `--pretty` | Indent the `-j` document for reading. Since v0.5.3 `-j` is **compact (one line) by default**. Env: `VIGOLIUM_JSON_PRETTY=1`. `--watch` stays one compact document per line |
| `--json-legacy-keys` | Restore the pre-envelope row aliases (`records`, `findings`, `scans`, `rows`, `stats`) alongside `items`, and flatten a single-object answer back to the top level. Since v0.4.6 they are **off by default** - they shipped a second full copy of every row on the wire. Env: `VIGOLIUM_JSON_LEGACY_KEYS=1` |
| `--max-output-bytes <n>` | *(read commands, with `-j`)* Cap the document at N bytes by dropping whole trailing items. The JSON stays valid and gains an `output_budget` object naming how many items came back, how many were omitted, and the next `--offset`. `0` = unlimited. Since v0.5.5 also on `fuzz`, `replay`, `endpoints`, `params`, `log ls`, `hosts` and `dns` |
| `--fields <list>` | *(read commands, with `-j`)* Restrict each row to these keys. Since v0.5.5 the names are a **shared vocabulary** across commands, aliases (`status`, `length`, `title`) are accepted and emitted under the name you passed, and an unknown name is an **error with the nearest match suggested** — never a silent drop. New keys: `uuid_short`, `response_headers` |
| `--usage` | *(any command, v0.5.5)* Print that command's flags, one line each, and exit. With `-j` it prints the [`schema flags`](#vigolium-schema-the-generated-contract) document — the same list as data |
| `-S, --stateless` | Run against a throwaway/standalone database. Since v0.4.5 it means the same thing on **every** command, and is accepted as a harmless no-op where it has none |
| `--events ndjson` | *(scan / run / scan-url / scan-request)* Stream machine events on stdout while the scan runs |
| `-v, --verbose` / `--debug` | Verbose logging / debug-level logging (debug also prints outgoing HTTP request lines) |
| `--silent` | Suppress everything except findings |
| `--dump-traffic` | Print every request/response pair to stderr, Burp-style (bypasses the logger) |
| `--log-file <path>` | Write all log output to a file, in JSON |
| `--color auto\|always\|never` | Since v0.5.3 colour is **automatic**, not always on: `auto` emits ANSI only when stdout *and* stderr are both terminals. `-j`, `--events` and `--ci-output-format` force `never`. `NO_COLOR`, `FORCE_COLOR` and `CLICOLOR_FORCE` are honoured under `auto` |
| `--no-color` | Same as `--color=never` (also honoured via `NO_COLOR`) |
| `--width <n>` | Maximum column width for table output (default `70`) |
| `--ci-output-format` | CI-friendly output: JSONL findings only, no colour, no banners |
| `-o, --output <path>` | *(read commands, with `-j`)* Write the result document to a file and print a receipt instead; `-` forces stdout. See [Saving a `-j` result](#saving-a-j-result-to-a-file) |
| `--read-only` | Open the database without modifying it - no directory creation, no journal-mode change, no WAL checkpoint, and no `-wal`/`-shm` siblings left behind. Read commands only (exit `2` elsewhere); use it when the source file is evidence |
| `--config <path>` / `--db <path>` | Override the config file / SQLite database path |
| `--project-uuid` / `--project-name` | Scope every operation to a project (see [Projects](/others/projects)) |
| `--scan-uuid <uuid>` | Pin the scan UUID for this session — use it to sync results across nodes |
| `--proxy <url>` | Route all requests through an HTTP/SOCKS5 proxy |
| `--format <list>` | Output format(s), comma-separated: `console`, `jsonl`, `html`, `report`, `pdf`, `markdown` (`md`), `sarif`, `csv`, `junit`, `github`, `sqlite` (needs `-S`), `fs`. Since v0.5.3 `import` and `js` use this global flag instead of local ones of their own. Since v0.5.5 the read commands also take **`tsv`** — see below |
| `--format tsv` | *(v0.5.5, on `traffic`, `finding`, `endpoints`, `params`, `hosts`, `dns`)* One tab-separated row per item, header line first (`--no-header` omits it). Pair it with `--fields` to pick the columns and their order. This is the shape to pipe into `cut`, `awk`, `sort` or a spreadsheet without a JSON parser in the way |
| `--ext <file>` / `--ext-dir <dir>` | Load a JavaScript extension / override the extension directory |
| `--mem-limit <size>` | Soft heap ceiling (`GOMEMLIMIT`) for scans: empty = auto (⅓ of RAM, scaled down by `-P/--parallel`), `off`, or an explicit `6GiB` / `50%`. An existing `GOMEMLIMIT` env var wins. |
| `--force` | Skip confirmation prompts |
| `--skip-dependency-check` | Skip the first-run dependency check (chromium, nuclei templates) and stamp `~/.vigolium/initialized` |
| `--soft-fail` | Always exit `0` (see above) |

<Note>
Mistype a long flag and Vigolium suggests the nearest match instead of a bare "unknown flag" error — e.g. `--module` yields `unknown flag: --module. Did you mean --modules? (run 'vigolium scan --help' for all flags)`. Added in v0.3.0. Since v0.4.7 a short name has to be within **one** edit of a candidate before it is offered, and a name with no near match points at the command's help rather than inventing one — `--url` used to be answered with "did you mean `--all`?".
</Note>

### Error codes under `-j`

A failed command under `-j` writes a parseable object to stdout and exits non-zero. Branch on `error.code`, never on the message — it is a **closed set**, shared with the REST API, and values are added but never re-worded. Print the authoritative enum with [`vigolium schema error`](#vigolium-schema-the-generated-contract).

The ones worth branching on:

| `error.code` | Exit | What it means |
|---|---:|---|
| `usage_error` | `2` | Bad flag, bad value, rejected combination. The message lists the valid set |
| `extension_load_failed` | `2` | A `--ext` extension failed to load; the scan was refused **before any request**. `--ext-allow-failures` scans without it |
| `source_missing` | `1` | Nothing at the pinned `--db` path. **Nothing is created** |
| `source_unreadable` | `1` | Not a database, or corrupt |
| `source_incompatible` | `1` | Valid SQLite that is **not** a Vigolium store — you are pointed at the wrong file. No tables are added to it |
| `no_targets_in_scope` | `1` | Scope refused **every** target, and no request was sent. The message names each target, the rule that refused it, and the config key to fix |
| `no_targets_reachable` | `1` | Every admitted target failed its reachability preflight. `--skip preflight` disables the check |
| `record_not_found` | `1` | *(`traffic body`/`headers`)* No record carries that `--uuid` |
| `body_unavailable` | `1` | *(same)* The record exists, but that side was never captured |
| `body_decode_failed` | `1` | *(same)* The announced encoding could not be undone — try `--representation stored` |
| `body_incomplete` | `1` | *(same)* Only a prefix is available — `--allow-incomplete` takes it anyway |
| `export_failed` | `1` | The run finished but a requested artifact was not written. **Retry the export, not the scan** |
| `pdf_failed` | `1` | The more specific `export_failed`: the headless-Chrome PDF render failed |
| `config_invalid` | `1` | *(`config validate`, and any run with a broken `--config`)* A setting breaks or silently weakens scans |
| `lint_failed` | `1` | *(`ext lint`, `auth lint`)* The file has errors. The document still lists every issue with line and column |
| `login_failed` | `1` | *(`auth load`, `auth check`, a scan with `--require-auth`)* The login flow did not authenticate |
| `not_ready` | `1` | *(`doctor`)* The environment is not ready. `--strict` also exits `1` on `degraded` |
| `not_found` | `1` | No such project, scan, skill or schema. `project use <unknown-uuid>` creates nothing — pass `--create` |
| `scan_not_found` | `1` | *(`scan status` / `wait` / `diff`)* No scan row carries that UUID |
| `scan_abandoned` | `1` | *(`scan wait`)* The row says `running` but nothing has written for 2 minutes, or its process is gone |
| `wait_timeout` | `1` | *(`scan wait`)* `--timeout` elapsed (default `30m`; `0` waits forever) |
| `gate_tripped` | `4` | A `--fail-on <severity>` gate matched. Output was written first |
| `budget_exhausted` | `5` | *(agent runs)* `--max-commands`, `--token-budget` or `--max-cost-usd` ran out. The run still finalized |
| `timed_out` | `5` | The work ran past `--max-duration` and stopped |
| `partial` | `5` | The work ran but did not cover everything it was asked to |
| `output_too_large` | `1` | The document could not be produced within `--max-output-bytes` |
| `failed` | `1` | Everything else |

<Warning>
  **A requested artifact that was never written fails the run (v0.5.0).** An export failure — an unwritable `-o`, a query that failed mid-stream — used to exit `0`, report `scan.finished status=completed` and leave no file: three success signals at once. `scan`, `run`, `scan-url`, `scan-request` and an agentic `-S` run now exit `1` with `error.code: "export_failed"`.

  **`export_failed` outranks `gate_tripped`.** The gate's whole premise is that the output was written before the code was chosen; when it wasn't, exit `4` would send a CI job to read a file that does not exist. Each `--format` is attempted independently, so with `--format jsonl,sqlite` one of them may well be on disk — the **Exports** summary on stderr lists the ones that landed. The findings reached the database either way.
</Warning>

<Warning>
  **A wrong `--db` path errors as of v0.4.7; it no longer reads as empty.** Opening a database used to create it, so a pure read against a typo'd or not-yet-scanned path returned `{"total":0,"items":[]}` with exit `0` — the same answer as a target nobody had scanned — and pointing `--db` at another tool's SQLite file wrote Vigolium's tables into it. Both now refuse, on `finding`, `traffic`, `traffic body`, `traffic headers`, `db list`, `db stats`, `db export`, `log`, `log ls` and `export`.

  `replay` and `fuzz` are exempt: they send traffic and record what they send, so bringing a store into being is a legitimate outcome for them. The built-in default database is also still created on first use.
</Warning>

### `vigolium schema`: the generated contract

Added in v0.5.3. Every shape above is published as **JSON Schema (draft 2020-12)**, reflected from the same Go types the commands emit — so a driver can validate what it parses instead of trusting this page.

```bash
vigolium schema                          # what has a schema: commands, event types, error, documents
vigolium schema command finding          # one command's -j document (envelope + typed items)
vigolium schema command scan status      # multi-word command paths need no quoting
vigolium schema event phase.progress     # one --events line type
vigolium schema event                    # any --events line: oneOf keyed on `type`
vigolium schema error                    # the -j error envelope; error.code is the closed enum
vigolium schema plan                     # the scan plan (scan --dry-run, the scan.plan event)
vigolium schema all > vigolium.schema.json
```

v0.5.5 adds the two views that describe the *tool* rather than its output:

```bash
vigolium schema flags fuzz -j            # one entry per flag: name, shorthand, type, default, inherited
vigolium fuzz --usage                    # the same list as prose, one line per flag
vigolium schema storage                  # every table of the DB this invocation would read
vigolium schema storage http_records -j  # one table: columns, row count, -j field names
```

- **`schema flags <command>`** takes the command path without `vigolium` (`schema flags traffic body`). `--usage` on any command prints the same thing, and under `-j` prints this exact document — so a driver can discover a command's flags without scraping `--help`.
- **`schema storage [table]`** maps the database: tables, columns, row counts, what each table holds, and the `-j` field a column surfaces as **where the two names differ** (`http_records.hostname` is `host` in `traffic -j`). It reads whichever store the invocation would read — the project DB, `--db`, or `$VIGOLIUM_DB_PATH`.

<Note>
  `schema storage` exists for the cases where SQL is the only way. Prefer the read commands: they apply project scoping, the severity and record-kind vocabulary, and the `-j` envelope that `--fields` and `--max-output-bytes` act on. A raw `SELECT` gets none of that.
</Note>

- Without `-j` the output is the **bare schema**, ready to hand to a validator. With `-j` it is the usual envelope, whose `items` are `{name, kind, envelope_kind, description, schema}`.
- Command schemas pin `schema_version` (`2`), `command`, `ok: true` and `kind`; a mutation's schema also requires `changed` and `action`.
- Objects are **closed** (`additionalProperties: false`), so a key the schema does not name is a contract change rather than a silent addition. Keys marked optional are omitted when empty.
- `--fields` may drop any item key, and `--json-legacy-keys` documents sit outside the contract.
- The same files are committed under [`docs/schema/`](https://github.com/vigolium/vigolium/tree/main/docs/schema) in the main repository, and a test fails when they drift from the code.

<Note>
  **Gate on the contract at startup, not on a parse error in production.** `vigolium schema command <name>` is the strong form; `vigolium version --json` remains the cheap one — it reports `schema_version` and `db_schema_version` without printing a schema.
</Note>

## Scanning

Run the full native pipeline against one or more targets.

```bash
# Single target
vigolium scan -t https://example.com

# Bare positional target URLs also work (deduped against -t/--target); also on scan-url/scan-request/run
vigolium scan https://example.com https://api.example.com

# Multiple targets (-t and -T/--target-file are both repeatable and combine)
vigolium scan -t https://example.com -t https://api.example.com
vigolium scan -T targets.txt
vigolium scan -T prod.txt -T staging.txt

# Scanning profiles and strategies
vigolium scan -t https://example.com --strategy deep
vigolium scan -t https://example.com --scanning-profile quick
vigolium scan -t https://example.com --scanning-profile full

# Phase control
vigolium scan -t https://example.com --only dynamic-assessment
vigolium scan -t https://example.com --skip discovery,spidering

# Module selection
vigolium scan -t https://example.com -m xss-light-url-params,sqli-error-based
vigolium scan -t https://example.com --module-tag spring --module-tag injection

# Host sweep: one request per target, passive fingerprinting only (see `run probe`)
vigolium run probe -T hosts.txt -c 20
vigolium run probe -T hosts.txt --json --no-response --tls-probe
vigolium scan -t https://example.com --probe                # ride the sweep along inside a wider scan

# Redirect handling (every phase, not just probe)
vigolium scan -t https://example.com --redirect-mode same-apex   # off|same-host|same-apex|any
vigolium scan -t https://example.com --record-redirect-chain     # each hop becomes its own record

# Output and reporting
vigolium scan -t https://example.com --format jsonl -o results.jsonl
vigolium scan -t https://example.com --format html -o report.html
vigolium scan -S -t https://example.com --format sqlite -o scan      # standalone .sqlite (stateless only)
vigolium scan -t https://example.com --format fs -o run             # browsable run-traffic/ + run-findings/ tree
vigolium scan -t https://example.com --format jsonl --export-only http,findings   # narrow the jsonl envelope

# Print results to stdout after the scan (pairs with -S --silent; also on scan-url/scan-request/run)
vigolium scan-url -S -t https://example.com --silent --print-finding        # findings as Markdown
vigolium scan-url -S -t https://example.com --silent --print-traffic-tree   # traffic as a host/path tree
vigolium scan-url -S -t https://example.com --silent --print-traffic        # raw request/response pairs

# Network controls
vigolium scan -t https://example.com --proxy http://127.0.0.1:8080
vigolium scan -t https://example.com -c 100 --rate-limit 200
vigolium scan -t https://example.com --rate-limit known-issue-scan=20   # cap ONE phase (repeatable, mixes with the bare form)
vigolium scan -t https://example.com --scanning-max-duration 2h
vigolium scan -t https://example.com --no-waf-pacing         # Disable proactive WAF/CDN pre-throttling (speed control)

# Machine event stream on stdout while the scan runs (human console stays on stderr)
vigolium scan -t https://example.com --events ndjson 2>/dev/null | jq -c .

# Discovery: sweep alternate HTTP(S) ports on the target hosts (deep intensity or --follow-subdomains)
vigolium scan -t https://example.com --intensity deep --port-sweep-ports 80,443,8080,8443

# CI/agent exit-code gating
vigolium scan -t https://example.com --fail-on high       # exit non-zero on any high+ finding
vigolium scan -t https://example.com --fail-on high --soft-fail   # surface the error but always exit 0

# Custom JS extensions
vigolium scan -t https://example.com --ext custom-check.js
vigolium scan -t https://example.com --ext-dir ./my-extensions
vigolium scan -t https://example.com --only extension --ext custom-check.js

# Project scoping
vigolium scan -t https://example.com --project-name my-project

# OAST and known-issue scanning
vigolium scan -t https://example.com --oast-url https://interact.sh/abc123
vigolium scan -t https://example.com --known-issue-scan-tags cve,misconfig --known-issue-scan-severities critical,high
vigolium scan -t https://example.com --known-issue-scan-templates cves/2024/,exposures/

# Rescan traffic already in the database — no -t/-T/-i
vigolium scan --all-records
vigolium run dynamic-assessment --all-records

# Request budgets (v0.5.3)
vigolium scan -t https://example.com --max-requests 20000
vigolium scan -T targets.txt --max-requests-per-host 2000

# Resolve the plan and print it — sends nothing
vigolium scan -t https://example.com --dry-run
```

<Warning>
  **`scan` and `run` no longer fall back to the database on their own (v0.5.3).** With no `-t` / `-T` / `-i` / stdin they exit `2`, and the message names the database and project a rescan would touch. Pass **`--all-records`** to rescan every HTTP record in the active project; it cannot be combined with `-t`, `-T`, `-i` or `-S` (exit `2`).

  On an interactive terminal the bare form still rescans for one release, with a deprecation warning. Under `-j`, `--events`, `--ci-output-format`, or when stdout or stderr is not a terminal, it is **already** an error — so a CI job or agent harness sees the new behavior today.

  **`vigolium scan <uuid>` exits `2`** as a mistyped subcommand rather than treating the UUID as a target.
</Warning>

<Warning>
  **A scan that cannot reach anything is now an error, not a clean empty result.**

  - **Scope admission** runs before a single request leaves, with the same matcher the scan then enforces. If **every** target is refused: exit `1`, `error.code: "no_targets_in_scope"`, nothing sent. The message names each target with the rule that refused it (`scope.host.include`, `scope.host.exclude`, `scope.path.include`, `scope.path.exclude`, `scope.cli_origin_mode`, `static_file`) and the config key to fix. If *some* are refused the rest are scanned, the scan is `partial` with reason `targets_out_of_scope`, and the exit code stays `0`.
  - **Reachability preflight** then sends one GET per admitted target. If none answer: exit `1`, `error.code: "no_targets_reachable"`. `--skip preflight` disables the check.
  - `scan-url` / `scan-request` **enforce scope without `-S`** as of v0.5.3; `--ignore-scope` scans a target the scope refuses. REST `POST /api/scan-url` and `/api/scan-request` answer **422** with `details: "no_targets_in_scope"` rather than accepting a scan that would do nothing.

  Both verdicts land on the scan row as the `preflight` phase outcome, and `scan.started` / `scan.finished` carry `targets_admitted` and `targets_rejected`.
</Warning>

**Request budgets.** `--max-requests` stops the scan after N requests to the targets (`0` = unlimited), and `--max-requests-per-host` does the same per host; config keys `scanning_pace.max_requests` and `scanning_pace.max_requests_per_host`. The cap is exact for gated traffic, the browser crawl is held to it within 500 ms, and **nuclei is not counted** (`request_cap_enforcement` on `scan.started` says so). A scan the budget stops is `partial` with `stop_reason: request_budget`. `--max-per-host` now defaults to `40` everywhere.

The repeatable "opaque" flags — `-H/--header`, `--auth`, `--auth-file`, `-t/--target`, `-T/--target-file`, `--spec-header`, and `--cookie` — take each value **verbatim**: commas are **literal**, not separators. So a target URL with a query like `?ids=1,2,3`, or a header/cookie whose value contains a comma, survives intact. To pass several values, **repeat the flag** (`-t https://a -t https://b`) rather than comma-joining them.

**Speed control — WAF-aware pacing.** The per-host rate limiter now **proactively pre-throttles** a host the first time earlier-phase traffic fingerprints it behind a recognized CDN/WAF edge (CloudFront, Cloudflare, Akamai, Imperva/Incapsula, Sucuri, or Azure Front Door — detected from headers on ordinary 200s), dropping that host's concurrency to `MaxPerHost/4` and ramping back up on healthy responses. This keeps an aggressive active phase from bursting the edge into a rate-based block that would hide findings. A one-time-per-host `[waf-pacing-armed]` notice prints the drop (e.g. `40→10`) to stderr and the session log. `--no-waf-pacing` disables this **proactive** pacing; the **reactive** back-off after a *confirmed* WAF block still applies. It's a Speed Control flag, available on `scan` / `scan-url` / `scan-request` / `run` / `ingest`.

**Discovery — alternate-port sweep.** `--port-sweep-ports` overrides the alternate HTTP(S) ports swept on the CLI target hosts (comma-separated). The sweep runs when `--intensity deep` is set or `--follow-subdomains` is on, so a host reachable on `8080`/`8443` (or any port you list) is discovered and scanned alongside the standard `80`/`443`.

### Pace: per-phase rate limits

The three speed dials — `-c/--concurrency`, `--rate-limit`, `--max-per-host` — each take an **optional phase qualifier** (v0.4.5), repeatable and mixable with the bare form:

```bash
# Cap the nuclei phase without capping the ~200 native modules, which pace themselves
vigolium scan -t https://example.com --rate-limit known-issue-scan=20

# 50 rps everywhere, 20 for the nuclei phase
vigolium scan -t https://example.com --rate-limit 50 --rate-limit kis=20
```

Qualifiers accept the same phase aliases `--only`/`--skip` do (`kis`, `cve`, `deparos`, `dast`, …). Resolution per phase is **phase-scoped → global → strategy/config default**. A qualifier naming a phase the run doesn't execute warns loudly rather than failing — a cap you believe is in force and isn't is worse than an error.

<Warning>
  **`--rate-limit` now applies at its documented default when you don't type it.** It used to be enforced only when explicitly passed, so *silence meant unlimited* while the help text advertised 100 — the fail-open direction on a safety knob. No cap now requires asking for it with `--rate-limit 0`; a negative value is a usage error (exit `2`), not "unlimited".
</Warning>

Under `--events ndjson`, `scan.started` reports the `pace` that actually applied plus a `phase_pace` table for any phase that differs, so you can **assert** what was in force rather than inferring it from the flags you passed.

### Machine event stream

`--events ndjson` on `scan` / `run` / `scan-url` / `scan-request` writes one JSON object per line to **stdout** while the scan runs. The human console keeps stderr byte-for-byte unchanged, so `2>/dev/null` yields clean NDJSON with zero non-JSON lines, and an interactive operator sees no difference.

```bash
vigolium scan -t https://example.com --events ndjson 2>/dev/null | jq -c .
```

```jsonc
{"v":1,"ts":"…","seq":1,"scan_uuid":"…","type":"scan.started","target":"https://…","strategy":"lite","phases":["heuristics-check","discovery","dynamic-assessment"],"db_path":"/tmp/…","pace":{"rate_limit":20,"concurrency":10,"max_per_host":10},"budgets":{…},"targets_admitted":1,"targets_rejected":0}
{"v":1,"ts":"…","seq":2,"scan_uuid":"…","type":"scan.plan","plan":{…}}
{"v":1,"ts":"…","seq":3,"scan_uuid":"…","type":"phase.started","phase":"discovery"}
{"v":1,"ts":"…","seq":4,"scan_uuid":"…","type":"phase.progress","phase":"discovery","requests_sent":1204,"findings":3,"done":1204,"total":4000,"unit":"requests"}
{"v":1,"ts":"…","seq":5,"scan_uuid":"…","type":"waf.block","host":"app.example.com","vendor":"cloudflare","status_code":403,"detail":"edge is filtering scan traffic — results for this host may be incomplete"}
{"v":1,"ts":"…","seq":6,"scan_uuid":"…","type":"waf.pacing","host":"app.example.com","vendor":"akamai","concurrency_from":40,"concurrency_to":8}

```

The full vocabulary is **20 types**. Print the generated schema for any of them with [`vigolium schema event <type>`](#vigolium-schema-the-generated-contract) — `vigolium schema event` alone gives every line as a `oneOf` keyed on `type`.

| Type | Read it for |
|---|---|
| `scan.started` | The canonical `phases[]` the aliases resolved to, the `db_path` to query afterwards, the `pace` and `budgets` that actually applied, and `targets_admitted` / `targets_rejected` from scope admission |
| `scan.plan` | **Always the second line**, before any request. Its `plan` is the object [`--dry-run`](#planning-a-scan-without-sending-anything) prints, with `scan_uuid` set |
| `scan.setup` | A first-run dependency is being fetched (`component` = `chromium` / `nuclei-templates`, `state` = `started` / `finished` / `failed`). Progress itself goes to stderr, so a cold machine's first `--events` run is still clean NDJSON |
| `phase.started` / `phase.finished` | Phase boundaries. `finished` carries `status`, `duration_ms`, `requests_sent`, `findings`, plus `reasons` and `limits` naming what curtailed it |
| `phase.progress` | Liveness. `requests_sent` every 5s is the real slope — a crawl that is working versus one that is wedged. `done` / `total` / `unit` when the phase can count itself |
| `finding.new` | Metadata only. Evidence lives in `db_path`; query it with `finding -j --with-records` afterwards |
| `module.error` | One module errored, timed out or panicked; `count` aggregates repeats. The scan carries on, and the total lands on the scan row as `module_errors` |
| `extension.failed` | A JS/YAML extension failed to load or threw. `explicit: true` means it came from `--ext`, which **aborts the scan** unless `--ext-allow-failures` is set |
| `waf.block` | The edge started filtering. Results for that host are **incomplete** — do not read a thin surface as a clean target |
| `waf.pacing` | Vigolium slowed itself down on purpose. Attribute the slowdown here, not to the target |
| `host.dead` / `host.quarantined` / `host.recovered` | The per-`host:port` circuit breaker opened, tripped or closed again. A quarantined host stops receiving traffic until it recovers |
| `auth.relogin` / `auth.session_suspect` | A session was detected as logged out and re-authenticated mid-scan (`ok` says whether it worked), or looks suspect but was kept |
| `oast.unavailable` | The OAST endpoint could not be reached, so out-of-band confirmations are not running |
| `import.summary` | *(`import`)* Totals for an import that streamed its work |
| `error` | A phase failed and the scan **carried on** — non-fatal by construction. A failure that ends the run rides on `scan.finished{status:"failed"}` instead |
| `scan.interrupting` | **Nonterminal.** SIGINT/SIGTERM arrived (`message` names the signal); graceful shutdown then runs and the real terminal event still follows |
| `scan.finished` | Terminal: `status`, `stop_reason`, `findings_by_severity`, `records_written`, `module_errors`, `exports` |

Contracts you can build on:

- **Every line carries `scan_uuid`**, stamped centrally so no call site can forget it. A sweep is several `vigolium scan` invocations; this is how you attribute an event to one.
- **`seq` is the stream's total order** — 1-based, stamped under the write lock, one per line. Order by it, not by `ts`: timestamps are millisecond-precision and a busy scan emits several events per millisecond, so sorting by `ts` reorders them. **A gap in `seq` means a line was lost.**
- **`v` is the event-schema version.** Gate on it.
- **`scan.finished` is always last**, including `status:"interrupted"` on SIGINT/SIGTERM, and it arrives **after finalization** — its totals are read back from the persisted scan row, so a run whose results never landed reports `failed` rather than `completed`.
- **Its absence means the process was killed outright** (SIGKILL can't be caught). Treat a stream that stops without a terminal event as a hard kill, not a completed scan.
- **New types and fields are added, never renamed.** A type you don't recognise is safe to ignore.

This replaces scraping `vigolium log` for `[waf-block-detected]` / `[waf-pacing-armed]` markers — every notice that reaches the log also reaches the stream. The WAF notifiers are deliberately **not** gated on `--silent`: that flag asks for a quiet terminal, and a driver passing `--silent --events` wants exactly that.

<Warning>
  **`--events` owns stdout exclusively.** Combining it with another writer of stdout — `-j/--json`, `--format jsonl` without `-o`, `--ci-output-format`, `--print-finding`, `--print-traffic`, `--print-traffic-tree` — is **rejected before any work starts**, exit `2` naming the conflict. It used to produce a corrupt interleaved stream and exit `0`. Exactly one protocol on stdout, always.
</Warning>

<Note>
  **A closed consumer does not kill the scan.** `vigolium scan --events ndjson | head -5` runs to completion and exits on its own merit; the truncated stream is reported on stderr as `event stream delivery failed: …; the scan ran to completion`, and the exit code is unaffected. SIGTERM shuts a native scan down gracefully with or without `--events`, including during setup before the first request.

  `--events` is refused under `-P/--parallel`. Each child's stdout is captured to its own per-target console log, so the parent's stdout — the one you're reading — would receive nothing, and the NDJSON would contaminate a file meant to be a human transcript.
</Note>

### Planning a scan without sending anything

```bash
# Print the resolved plan and exit — no requests, no scan row, no UUID
vigolium scan -t https://example.com --dry-run
vigolium scan -t https://example.com --intensity deep --dry-run -j
vigolium run discovery -t https://example.com --dry-run
```

Added in v0.5.3. `--dry-run` resolves everything a real run would and prints it: the phases (with **why** each disabled one is off), budgets, pace, modules, scope, auth session names, the scope-admission verdict and a rough request estimate.

It is inert by construction — it **mints no scan UUID, writes no output file or scan row, materializes no wordlist, runs no login and registers no OAST**; an existing database is only read. Under `-j` the document carries `items` (the phases), `plan` (the whole object) and `dry_run: true`.

The same object rides a real run's event stream as `scan.plan` — always the second line, before any request — and is stored on the scan row, so `scan status` and the finished scan document hand it back afterwards. `vigolium schema plan` prints its schema.

### Watching a scan from elsewhere: `scan status`, `scan wait`

When the scan was launched in the background, by another tool, or on a `--scan-uuid` you chose, poll it instead of holding its stream.

```bash
# Where is it, and is it still alive?
vigolium scan status <uuid>
vigolium scan status <uuid> -j

# Block until it finishes, then print the scan document and exit with its outcome
vigolium scan wait <uuid> --timeout 45m -j

# The agent pattern: launch detached, then block
vigolium scan -t https://app.example --scan-uuid $ID >/dev/null 2>&1 &
vigolium scan wait $ID --timeout 45m -j

# CI gate on the finished scan
vigolium scan wait $ID --fail-on high --fail-on-partial

# Progress as NDJSON for a driver
vigolium scan wait $ID --events ndjson
```

Every native scan keeps a **heartbeat**, whether or not `--events` or `persist_logs` is set: every 10s and on each phase change it atomically rewrites `<sessions_dir>/<uuid>/status.json` (phase, requests sent, findings, progress, PID, host) and stamps the scan row's `heartbeat_at`, `current_phase`, `pid`, `runner_host` and `total_requests`. That file is what answers for a `-S` or `--db-isolate` scan, whose row is not in the store you are reading until the run ends.

`scan status -j` returns one item: `status` (stored) and `effective_status` (`running` / `abandoned` / `completed` / `failed` / `cancelled`), `liveness {last_write_at, stale, sources, process_gone}`, `phase`, `phases_done`, `requests_sent`, `findings`, `findings_by_severity`, `progress`, `eta`, `plan` (the stored plan, verbatim), `completeness`, `stop_reason`, `started_at`, `duration_ms`, `db_path`.

<Note>
  **The ETA is never invented.** `eta.upper_bound_ms` is the tighter of the remaining `--scanning-max-duration` budget and the stored plan's ceilings for what is left. `eta.estimate_ms` extrapolates the current phase's own rate — `elapsed × (total−done)/done`, which needs a known total — and adds the later phases at 0.6 of their ceilings, clamped to the upper bound. **Either is `null`** when something it rests on is unknown; `eta.basis` names what the figures stand on (`phase_rate`, `plan_ceilings`, `scan_budget`, or `unknown`). A finished scan reports `0`/`0` with `basis: "finished"`.
</Note>

**Abandoned** means the row says `running` but nothing has written for 2 minutes (heartbeat, `status.json`, `runtime.log`, the newest `scan_logs` line) — or the scan ran on this host and its PID is gone, in which case immediately. The same verdict feeds `log ls -j` (`last_write_at`, `stale`, `effective_status`, `liveness_sources` per row) and `log <uuid>`'s auto-follow.

`scan wait` polls through the **read-only** database pool, so it never contends for the write lock the running scan needs. It prints progress to stderr and, on a terminal state, prints the finished [scan document](/getting-started/cheat-sheet#the-scan-document) on stdout under `-j` — the same envelope `scan -j` prints, rebuilt from the row, so a driver that *waited* parses exactly what one that *ran* the scan would. `-n/--limit`, `--fields` and `--compact` shape it the same way. Then it exits:

| Exit | When |
|---:|---|
| `0` | completed |
| `1` | failed or cancelled (`failed`), the process died while the row still said running (`scan_abandoned`), or `--timeout` elapsed (`wait_timeout`, default `30m`; `0` waits forever) |
| `4` | `--fail-on <severity>` matched a finding of the finished scan |
| `5` | `--fail-on-partial` and the scan completed with partial coverage (`partial`) |

An unknown UUID is tolerated for 30s — the row may not exist yet — then fails `not_found`. `--events ndjson` streams `phase.progress` lines on stdout instead and ends with `scan.finished`, or with an `error` line whose `error_kind` is `wait_timeout` / `scan_abandoned`; it cannot be combined with `-j`.

**Cleaning up dead scans.** `vigolium log ls --reap` finalizes every `running` row of the project whose liveness says abandoned — `status: failed`, `completeness: partial`, `stop_reason: "abandoned"`, `finished_at` set to its last write. It also prunes `status.json` files older than `scanning_strategy.scan_logs.status_retention_days` (default `30`; `0` keeps them), the same prune `vigolium server` runs at start. `-j` adds `reaped` (UUIDs) and `status_files_removed`. `--reap` writes, so `--read-only` and `-S` / `--glob-db` refuse it (exit `2`).

### Comparing two scans: `scan diff`

```bash
# Two scans by UUID or 8+ character prefix
vigolium scan diff 6f1c2a90 9551f38a

# Keywords: the most recent finished scan, and the one before it
vigolium scan diff previous latest

# The N-th most recent scan of a target against its most recent
vigolium scan diff --target https://app.example --last 3

# CI gate: fail when a new finding is high or above
vigolium scan diff previous latest --fail-on-new high
```

Added in v0.5.3. Each finding lands in one of four buckets:

| Bucket | Meaning |
|---|---|
| `new` | Observed by the head scan, not by the base scan |
| `unchanged` | Observed by both |
| `fixed` | Observed by the base and not the head, **and the head scan is comparable** — it completed, covered every base target, and completed every phase the base ran |
| `not_reobserved` | The same absence, when the head scan is **not** comparable (curtailed, narrower, still running) |

<Warning>
  **`fixed` and `not_reobserved` are the same observation with different warrants.** A finding missing from a scan that stopped early, or never reached that target, is not evidence of a fix — it is evidence of nothing. Only act on `fixed`.
</Warning>

A scan is named by full UUID, an 8+ character prefix, or a keyword: `latest` (the most recently *started* scan that is not running) and `previous` (the one before it). `--fail-on-new <severity>` exits `4` after the result is written. `"history": "partial"` on a row means that scan predates the store's per-scan observation history, so a finding it re-detected may be missing from the comparison.

Findings marked `false_positive` or `accepted_risk` are left out unless `--include-dismissed`.

### Parallel & isolated scans

Scan many targets at once, or let several parallel scans share one database without write contention.

```bash
# Fan out a target list across N isolated child processes, one per-host output file each
vigolium scan -T targets.txt -P 4 --stateless --split-by-host --format jsonl -o results

# Parallel into one shared DB: each worker scans into a private temp DB, then merges into --db
vigolium scan -T targets.txt -P 4 --db-isolate --db shared.db --format jsonl,html -o report

# Single scan into a private temp DB merged back into --db (no write contention)
vigolium scan -t https://example.com --db-isolate --db shared.db

# Resume an interrupted stateless fan-out (skips targets that already completed)
vigolium scan -T targets.txt -P 4 --stateless --split-by-host --format jsonl -o results --resume
vigolium scan --resume                                              # auto-discover *.progress.json in cwd
```

- `-P, --parallel N` — scan up to N targets concurrently as isolated child processes. Requires one of two isolation shapes, never a mix: `-S -T --split-by-host` (per-host output files, nothing persisted) **or** `--db-isolate -T` (every target merges into one shared `--db`). Real in-flight requests ≈ `N × --concurrency`.
- `--db-isolate` — scan into a private temporary SQLite DB and merge results into `--db` at the end (SQLite only). Under `--stateless` it is **ignored with a warning** since `-S` keeps no database to merge from; before v0.4.8 the pair aborted the run.
- `--split-by-host` — in stateless multi-target mode, write a separate `base-<host>.<ext>` output file per target.
- `--resume` — resume a prior `-S -T --split-by-host -P` run from its `<output>.progress.json` manifest, scanning only the targets that didn't finish. Run bare (no other flags) to auto-discover the manifest in the current directory and relaunch the saved run.

## Running a Single Phase

`vigolium run <phase>` is an alias for `scan --only <phase>`, useful when you want one specific stage of the pipeline.

```bash
vigolium run probe -T hosts.txt                    # host sweep, one request per target
vigolium run discover -t https://example.com
vigolium run spidering -t https://example.com
vigolium run dynamic-assessment -t https://example.com
vigolium run dynamic-assessment -t https://example.com --module-tag spring
vigolium run external-harvest -t https://example.com
vigolium run known-issue-scan -t https://example.com
vigolium run known-issue-scan -t https://example.com --known-issue-scan-tags cve --known-issue-scan-severities critical,high
vigolium run extension -t https://example.com --ext custom-check.js
vigolium run deparos -t https://example.com
vigolium run dast -t https://example.com
```

Phase names accept generous aliases - `httpx`/`alive`/`sweep` reach the probe, `crawl` reaches spidering, `cve`/`kis` reach the known-issue scan. `vigolium strategy --json` prints the authoritative set as `phases[].canonical` / `phases[].aliases`; see [Phase Aliases](/native-scan/scanning-modes-overview#phase-aliases).

### `run probe` - the host sweep

`vigolium run probe` is the native prober: **one request per target**, passive technology fingerprinting and attack-surface scoring, no content discovery and no fuzzing. Built for host lists in the thousands, where `run discover` would spend its whole budget on the first handful.

```bash
vigolium run probe -T hosts.txt --json --no-response          # stdout = JSONL, stderr = progress
vigolium run probe -T hosts.txt --json --tls-probe -c 50      # + TLS certificates
vigolium run probe -T hosts.txt -S --format sqlite -o sweep   # keep the DB for triage
```

| Flag | Effect |
|---|---|
| `--probe` | Enable the sweep phase inside a wider scan |
| `--tls-probe` | Handshake each HTTPS target; report version/cipher + the leaf certificate (subject/CN, SANs, issuer, validity, serial, fingerprints). Validation is deliberately off - an expired or self-signed cert *is* the result |
| `--redirect-mode` | `off` \| `same-host` \| `same-apex` \| `any` (default `any`). Applies to **every** phase. `same-apex` follows `www.example.com` -> `example.com` but not `example.com` -> `tracker.example.net` |
| `--record-redirect-chain` | Each followed hop becomes its own `http_records` row, chained by `parent_uuid` |
| `--no-response` | Drop raw request/response bytes, keep every derived field (alias of `--omit-response`) |
| `--export-only` | Limit the `--format jsonl` envelope to chosen record types (`http`, `findings`, `scans`, `modules`, `oast`, `source-repos`, `scopes`) |

<Note>
  **A probe-only run flips its own defaults** (`run probe`, `scan --only probe`): redirect hops recorded, `--redirect-mode same-apex`, the many-hosts connection profile, and **proactive WAF pacing off** - a sweep sends one request per host, so there is no burst to pre-empt and the pre-arm would print a pacing notice *per host*. Reactive back-off after a confirmed block still applies. Its JSONL envelope also narrows to `http_record` objects; `--export-only http,findings` restores the findings. Each default yields to an explicit flag, and none of them apply when the probe rides along inside a wider scan.

  `--tls-probe` and `--record-redirect-chain` on a run with no probe phase **warn that they are inert** instead of silently doing nothing.
</Note>

Probe rows are labelled `source: probe`, so a sweep is separable from a real scan in the same project. Rank a finished sweep with `vigolium traffic --source probe --sort surface_score`. Full details on the [Probe phase page](/native-scan/phases/probe).

## Input Modes

Feed traffic into a scan from OpenAPI, Burp, curl, HAR, or stdin.

```bash
vigolium scan -I openapi -i openapi.yaml -t https://api.example.com
vigolium scan -I burp    -i burp-export.xml -t https://example.com
vigolium scan -I curl    -i requests.txt
vigolium scan -I har     -i traffic.har
cat urls.txt | vigolium scan -i -
```

Run `vigolium --list-input-mode` to see every supported input format with examples. Accepted formats are `urls`, `openapi`/`swagger`, `postman`, `curl`, `burpraw`/`raw`, `burpxml`/`burp`, `burpscope`/`burp-scope`, `har`, `nuclei`, and `deparos`.

An unknown `-I/--input-mode` value is **rejected up front** with a clear error (it previously fell through to the Nuclei parser silently, so a typo could yield zero or partial records with no warning).

<Warning>
  **`-i/--input` vs `-T/--target-file` is not a free choice.** `-T` reads its file as one target URL per line, so a spec or an export must go through `-i` — pointing `-T` at a YAML spec makes every line of that file a target (and under `-S` fans out one child scan per line). The two exceptions are the formats that genuinely *are* target lists: `urls` and `burpscope`.
</Warning>

<Note>
  **`-T` actually seeds the scan since v0.4.6.** It used to populate the input source but never `Options.Targets`, so `vigolium run spidering -T hosts.txt` finished in 0s printing a truthful-looking `Targets: N` banner and crawling nothing. Piped URL lists (including an explicit `-I urls`) promote the same way now, and an unparseable line is skipped rather than aborting the whole scan on the first junk URL in a recon export.
</Note>

#### Schemeless targets

A target without a scheme — `example.com`, `example.com:8443`, or a `-T` file of bare hostnames straight out of a subdomain tool — is normalized to **`http://`** before anything else runs:

```bash
vigolium scan -t example.com          # scanned as http://example.com
vigolium run probe -T subdomains.txt  # every bare hostname normalized
```

`http` rather than `https` keeps the normalized form byte-identical to the request the HTTP path already built for a bare host; a host that only answers on 443 redirects there on the first hop, which [`--redirect-mode`](/native-scan/phases/probe) follows. Normalization runs **before** the target dedup, so `example.com` and `http://example.com` are one target, not two, and the normalized spelling is what the banner prints. A target that already names a scheme is left untouched, whatever that scheme is.

<Note>
  **Before v0.4.8 a bare hostname silently skipped spidering.** Probe, discovery and known-issue-scan tolerated it, but the browser phase parses its seed with stricter rules — `example.com` reads as a *path* with no host, and `example.com:8443` fails harder still on the colon. Spidering therefore hard-failed per target on the exact host lists every other phase scanned, and because a failed crawl is reported as a completed one with 0 records, `scan --only spidering --soft-fail` exited `0` with an empty export. If you have a pipeline that quietly produced no crawl results from a hostname list, this was why.
</Note>

<Tip>
  The `gau` [tool shim](#tool-shims) is the one exception: it defaults a bare domain to **`https://`**, because `gau`'s own callers write bare domains for sites they reach over TLS.
</Tip>

### `burpscope` — scan a bug-bounty scope file

`burpscope` parses a **Burp Suite project-config scope export** — the `{"target":{"scope":{"include":[…],"exclude":[…]}}}` JSON a bug-bounty program hands out, *not* the proprietary binary `.burp` project file — and expands its include rules into seed URLs:

```bash
vigolium scan -T scope.json                  # content-sniffed, no -I needed
vigolium scan -i scope.json -I burpscope     # or name it explicitly
```

It is content-sniffed on both the `-T` and `-i` paths, so it works without `-I`; an explicit `-I` always wins. Three rules govern the expansion:

- **A wildcard host is never guessed at.** `^.*\.example\.com$` names a set, not a server — synthesizing the apex would send traffic at a host the scope never listed. Those are reported separately rather than scanned.
- **An `http://` candidate collapses into its `https://` twin** when the same host and path are in scope over both (Burp writes both for every host, and the http one is a redirect in practice). An explicit non-default port survives as its own distinct service.
- **Exclude rules are applied to the derived targets** before anything is emitted.

A scope file that yields zero targets is a hard error, not an empty run.

## Ingestion

Push HTTP traffic into the database without running a scan, useful for building a project corpus before scanning, or for sending traffic to a remote server.

```bash
vigolium ingest -t https://example.com -I openapi -i spec.yaml
vigolium ingest -t https://example.com -I burp    -i export.xml
cat urls.txt | vigolium ingest -i -

# Send to a remote Vigolium server
vigolium ingest -s http://server:9002 -i api.yaml -I openapi

# After ingesting, scan the records (local mode only)
vigolium ingest -t https://api.example.com -I openapi -i spec.yaml --scan-on-receive
```

### Batch ingest — N sources, one process

Since **v0.4.5** `-i` is repeatable and `--dir` walks a directory, so a folder of captures costs one process instead of N:

```bash
# Repeated -i, ingested in the order given
vigolium ingest -i a.har -i b.har -i c.yaml

# Or point at a directory (non-recursive, sorted, so re-runs are reproducible)
vigolium ingest --dir ./captures --dir-glob '*.har' -I har
```

| Flag | Default | What it does |
|---|---|---|
| `--dir <path>` | — | Ingest every matching file in this directory, in one process |
| `--dir-glob <pattern>` | `*` | Filename pattern for `--dir`, e.g. `'*.har'` |
| `--keep-blocked` | off | *(v0.5.5)* Store a fetched response the block detector classifies as a WAF/bot wall, remarked `blocked:<reason>`, instead of dropping the record |

<Note>
  **`ingest -j` lists what landed (v0.5.5).** The document's `items` are the stored records, and each failure carries the reason it failed — so a partial ingest is readable rather than a count. A source whose responses were all WAF-blocked now reports the **dominant block reason** instead of "no response to store", which used to look like the capture was empty.

  `--keep-blocked` is the companion: the block page itself is evidence of a control you may want to characterise, and dropping it leaves no trace that anything was there.
</Note>

A failing source does **not** discard its siblings — one bad HAR in fifty must not cost the other forty-nine — but the command still exits non-zero and names how many failed. An empty `--dir` match is a **hard error**: "ingested 0 records" for a typo'd path is indistinguishable from an empty capture.

<Note>
  `--dir` is deliberately non-recursive. Walking subdirectories would silently widen what you pointed at, and record ids are assigned in ingest order.

  Concurrent `vigolium ingest` processes against one SQLite file are safe anyway (every open sets `busy_timeout`, WAL, and an immediate write lock, so writers serialize rather than failing with `SQLITE_BUSY`). Batch mode is still the right shape — it pays one process start and one schema check, not N.
</Note>

<Warning>
  **`-S` on `ingest` and `server` is a deprecated alias for `--scan-on-receive`** and warns. Everywhere else in the CLI `-S` means `--stateless`. Use the long `--scan-on-receive` spelling on these two commands.
</Warning>

## Server

Start the REST API and ingest proxy.

```bash
vigolium server                                              # Binds 127.0.0.1:9002 — loopback only
vigolium server --host 0.0.0.0 --service-port 8443           # Deliberately expose it
vigolium server --no-auth                                    # Local use only — disables bearer auth
vigolium server -t https://example.com --scan-on-receive     # Auto-scan ingested traffic
vigolium server --scan-on-receive --passive-only             # Passive modules only — no active traffic; includes secret detection
vigolium server --mirror-fs ./mirror                         # Live-mirror ingested traffic + findings to a filesystem tree
vigolium server --burp-bridge-url http://127.0.0.1:9009      # Merge live Burp Proxy history into GET /api/http-records
vigolium server --discard-queued                             # Drop tasks a previous run left in the spill queue

# Transparent ingest proxy (records traffic flowing through it)
vigolium server --ingest-proxy-port 9003

# Intercept HTTPS too via a generated MITM CA
vigolium server --ingest-proxy-port 9003 --proxy-mitm
vigolium server --ingest-proxy-port 9003 --proxy-mitm --proxy-insecure   # skip upstream TLS verification

# Non-loopback ingest proxy: access control is required, not optional
vigolium server --host 0.0.0.0 --ingest-proxy-port 9003 --proxy-token "$TOKEN"
vigolium server --host 0.0.0.0 --ingest-proxy-port 9003 --proxy-allow 10.0.0.0/8

# The MITM CA
vigolium server ca path                      # where it lives
vigolium server ca print --out ./vigolium-ca.pem
vigolium server ca install                   # print the commands that trust it; --yes runs them
vigolium server ca uninstall

# Narrowed deployments
vigolium server --view-only                                  # Read-only: no scanning, ingestion, agent, or write endpoints
vigolium server --no-agent                                   # Disable every agent endpoint (and warm-session pooling)
vigolium server --no-swagger                                 # Disable the Swagger UI and API spec endpoint
vigolium server --demo-only                                  # Expose only the demo read allowlist
vigolium server --alternative-ingest-key k1 --alternative-ingest-key k2   # Extra ingestion-only API keys
```

See [Transparent Proxy](/server-mode/proxy) for the full MITM workflow.

<Warning>
  **The server binds `127.0.0.1` by default as of v0.5.3** — it used to bind `0.0.0.0`. Pass `--host 0.0.0.0` (or set `$VIGOLIUM_SERVER_HOST`) to expose it deliberately.

  **A non-loopback ingest proxy needs access control.** Bound anywhere but loopback, the proxy requires `--proxy-token <secret>` (sent as `Proxy-Authorization`, Basic with any username or Bearer; config `server.ingest_proxy_token`) or `--proxy-allow <cidr|ip>` (repeatable; config `server.ingest_proxy_allow`). An open MITM proxy on a routable address is an open relay that also decrypts TLS.

  **`-S` on `server` and `ingest` is now a usage error.** It used to be a deprecated alias for `--scan-on-receive`, which collided with the global `-S/--stateless` meaning. Spell `--scan-on-receive` out.
</Warning>

**The MITM CA is managed by `vigolium server ca`** (v0.5.3), which replaces the old `--export-ca` flag: `print` writes the PEM to stdout or `--out FILE` (`-j` gives `path`, `sha256`, `subject`, `not_after`), `path` says where it lives, and `install` / `uninstall` print the commands that trust or untrust it on this OS — `--yes` runs them for you.

**The scan-on-receive spill queue** lives at `~/.vigolium/server-queue/` and **resumes on restart**, so work queued when the server went down is not lost. `--discard-queued` drops what a previous run left behind; tasks older than 24h are always dropped.

**Narrowing the exposed surface.** `--view-only` is the strictest: the server answers reads and nothing else — scanning, ingestion, agent runs, and every write endpoint are refused. `--no-agent` keeps the scanner and ingestion but removes all `/api/agent/*` routes plus agent subprocess warm-session pooling (`--disable-warm-session` turns off only the pooling, keeping the endpoints). `--no-swagger` drops the Swagger UI and the spec route. `--demo-only` exposes just a read allowlist — `GET /api/findings[/:id]`, `/api/http-records[/:uuid]`, `/api/modules`, `/api/stats`, `/api/extensions[/:name|/docs]` — for a public demo instance. `--alternative-ingest-key` (repeatable) adds extra API keys accepted **only** on the ingestion endpoints, so a collector can push traffic without holding the main key.

<Note>
  `--catchup-threads` and `--disable-catchup` are deprecated no-ops kept for compatibility — catch-up scanning is disabled. They still appear in `--help` and in older examples.
</Note>

`--burp-bridge-url <url>` (alias `--caido-bridge-url`) points the server at a running Burp Suite's or Caido's loopback **live bridge** (default listener `http://127.0.0.1:9009`, exposed by the [`burp-vigolium`](https://github.com/vigolium/burp-vigolium) extension or the [`caido-vigolium`](https://github.com/vigolium/caido-vigolium) plugin) and merges its live proxy rows into `GET /api/http-records` — labelled `source: burp` or `source: caido` according to which listener answered — for the UI and API. The flag also reads the `VIGOLIUM_BURP_BRIDGE_URL` env var as a fallback. See [Using Vigolium with Burp Suite](/getting-started/burp-suite) or [with Caido](/getting-started/caido-plugin) for bridge setup.

`--passive-only` (with `--scan-on-receive`) restricts scanning to **passive modules only** — no active scan traffic is sent, and secret detection is included. It's the safest way to analyze forwarded Burp/proxy traffic in place. Combining it with `--full-native-scan-on-receive` still crawls (discovery + spidering send requests); for zero active traffic, use `--scan-on-receive` without the full-native flag.

## Database & Results

Browse, export, and prune scan data.

```bash
# Browse
vigolium db ls
vigolium db ls findings           # Positional table selector: findings | scans | scopes (--table is deprecated)
vigolium db stats
vigolium db stats --detailed
vigolium traffic                  # Alias for `db ls http_records`
vigolium traffic login            # Filter to login-related records
vigolium finding                  # Fuzzy-search findings
vigolium finding xss --markdown   # Render matches as Markdown (evidence + http blocks) to stdout

# Severity: --severity is an explicit set (alias --sev on `finding`); --min-severity is a floor
vigolium finding --severity high,critical                        # exactly these severities
vigolium finding --sev h,c                                       # single-letter shorthands
vigolium finding --sev crit,me,info                              # unambiguous prefixes
vigolium finding --min-severity high --confidence certain,firm   # floor (high+critical) + confidence
vigolium db ls findings --severity high,critical                 # --severity also on `db ls`

# Record kind & producing-module type (on `finding` and `db list`)
vigolium finding --record-kind finding,candidate                 # kinds: finding (default), candidate, observation
vigolium finding --module-type active,passive                    # by producing module type
vigolium db ls findings --module-type nuclei,agent               # also on `db ls`

# Exclude filters (on `finding` and `traffic`) — inverse of --search/--header/--body
vigolium finding --search sqli --exclude-search login            # keep sqli, drop anything mentioning login
vigolium traffic --exclude-header Authorization                  # drop rows carrying an Authorization header
vigolium traffic --exclude-search .css --exclude-search .js      # repeatable — drop if ANY term matches

# Select one exact URL (equality, repeatable, applied before pagination)
vigolium traffic --url 'https://api.example.com/v1/me'
vigolium traffic --url 'https://a.example/x' --url 'https://a.example/y'

# Extract one stored message — no re-send
vigolium traffic body --uuid <uuid> -o response.json
vigolium traffic headers --uuid <uuid> --name set-cookie -j

# Save a -j result to disk instead of into a transcript
vigolium finding -j -n 500 -o findings.json

# Count instead of listing — the same filters, a dozen integers back
vigolium traffic --group-by status_code --host api.example.com
vigolium traffic -j --group-by response_content_type --group-limit 5

# Attack surface (see "Surface score vs risk score" below)
vigolium db ls --min-surface 50 --sort surface_score -n 20
vigolium traffic --source probe --sort surface_score -n 50

# Read a standalone export directly (project scoping off, never writes to your DB)
vigolium finding -S --db ./scan.jsonl --min-severity high
vigolium traffic -S --db ./scan.sqlite --status 500 -n 20

# Export
vigolium export --format jsonl -o full-export.jsonl
vigolium export --format jsonl --only findings
vigolium export --format jsonl --only findings,http
vigolium export --format html -o report.html
vigolium export --format fs -o run            # browsable run-traffic/ + run-findings/ tree (also on `db export`)
vigolium export --format html,markdown,bundle -o acme-q3   # several formats, one DB read

# Live Burp bridge — read Burp history into the traffic view, or push DB traffic back into Burp
vigolium traffic --burp-bridge-url http://127.0.0.1:9009                                # merge live Burp Proxy history
vigolium traffic --burp-bridge-url http://127.0.0.1:9009 --save-to-vigolium-db          # persist the current page into the DB
vigolium traffic --burp-bridge-url http://127.0.0.1:9009 --save-to-vigolium-db --all    # persist every matching record
vigolium traffic --burp-bridge-url http://127.0.0.1:9009 --save-to-burp                 # copy DB traffic into Burp's Site map

# Cleanup — a selector is required; a bare `db clean` is rejected
vigolium db clean --scan-uuid my-scan
vigolium db clean --host api.example.com
vigolium db clean --all --force                    # delete every row from the data tables
vigolium db reset --force                          # delete + recreate the DB file (SQLite; VACUUMs automatically)
```

`finding`/`traffic` accept `-S/--stateless` + `--db <file>` to read a `--format jsonl` export or a standalone `.sqlite` directly, and `--markdown` to print the matched items as Markdown (under `-S`, add `--compact` to window long responses around the match).

**Severity filters.** `--severity` (alias `--sev` on `finding`) takes an explicit comma-separated set, accepting single-letter shorthands (`h,c`) and any unambiguous prefix (`crit`, `me`, `info`). It differs from `--min-severity`, which is a **floor** — `--min-severity high` expands to `high,critical`. When both are given, `--severity` wins. `db ls` carries `--severity` too (findings tables).

**Record-kind & module-type filters.** `--record-kind` (on `finding` and `db list`) filters by record kind — `finding`, `candidate`, or `observation` (comma-separated; default `finding`). `--module-type` (same commands) filters by the **producing module type** — `active`, `passive`, `nuclei`, `agent`, `source-tools`, `oast`, or `extension` (comma-separated).

**Exclude filters.** `--exclude-search` / `--exclude-header` / `--exclude-body` (on `finding` and `traffic`) are the inverse of `--search` / `--header` / `--body`: they **drop** any row where the term appears. `--exclude-search` is repeatable, and a row is dropped if **any** term matches (contrast `--search`, whose repeated terms AND-narrow the kept set).

**Dropping the not-found pages (v0.5.5).** `traffic --exclude-not-found` drops the records that are their origin's not-found page: a `404`/`410`, or a response matching the not-found baseline [`vigolium fingerprint`](#host-facts-fingerprint-hosts-dns) stored for that origin. `--fields matches_not_found` reports the same judgement per row without dropping anything. On a soft-404 origin — one that answers `200` to everything — this is the only filter that works, because every status filter you could write says `200`.

**Record UUIDs take a prefix (v0.5.5).** Every flag that names a stored record by UUID accepts a **unique prefix of at least 8 characters**, so `--uuid 3f9a0c2b` is enough where the full value used to be required. A prefix matching more than one record is refused with `error.code: "ambiguous_id"` and the candidates listed — never resolved to the first match.

### Finding lifecycle: `finding mark`, `finding verify`

Added in v0.5.3. A finding now carries a **status** through its life, so a triage verdict survives the next scan instead of living in a spreadsheet.

```
draft → triaged → confirmed → fixed
             ↘ false_positive
             ↘ accepted_risk      (both "dismissed")
```

```bash
# Record a verdict
vigolium finding mark 42 --as false_positive --note "static asset, no user input"
vigolium finding mark 3f9a0c2b71de 42 43 --as confirmed --by alice -j

# Re-run a finding's own module and see whether it still reproduces
vigolium finding verify 42
vigolium finding verify 3f9a0c2b71de 43 --mark -j
vigolium finding verify --scan-uuid 6f1c… --fail-if not_reproduced
vigolium finding verify 42 --dry-run        # print the reconstruction, send nothing

# Read them back
vigolium finding --verdict confirmed,triaged
vigolium finding --new-since previous --include-dismissed
```

| Verdict | Means |
|---|---|
| `false_positive` | Not a bug — scanner noise, or not exploitable |
| `confirmed` | Reproduced: a human or a re-verification saw it happen |
| `accepted_risk` | Real, and the owner has decided to keep it |
| `fixed` | Resolved |
| `triaged` | Looks real, not yet reproduced |

<Warning>
  **`false_positive` and `accepted_risk` are "dismissed", and dismissed findings are left out by default** — of the `--fail-on` gate, of [`scan diff`](#comparing-two-scans-scan-diff), and of `finding --new-since`. Pass `--include-dismissed` to keep them. Reports still include them, labelled.

  This is the change most likely to shift a pipeline's numbers after an upgrade: a CI gate that used to trip on a known-good finding stops tripping once someone marks it.
</Warning>

A finding is named by its numeric `id` (the ID column) **or its `finding_hash`** — the full hash, or a prefix of at least 12 characters. Prefer the hash in anything durable: it is stable across databases, merges, exports and machines; the id is a per-database autoincrement and is not. A prefix matching more than one finding is refused with the candidates listed, and an id or hash that matches nothing exits `1` *after* the result is written, so a typo is never mistaken for success.

Every change is stamped with `--note` and `--by`, kept on the finding as `status_note` / `status_actor` and appended to its status history. A finding already at the verdict is reported `unchanged` and left alone.

**`finding verify`** re-runs the finding's own module against its target and records whether it reproduces — `confirmed`, `not_reproduced`, `inconclusive`, or `unsupported` (no deterministic re-run exists: agent, audit, OAST and known-issue-scan findings, or an `ext-*` module that is not loaded). The baseline and insertion point come from the replay context stored with the finding; the module runs **alone**, on that one point, with cross-module dedup off, against a fresh baseline response. A passive finding is re-analyzed on its stored record without sending anything (`--refetch` fetches a fresh response first).

The verdict goes to the finding's `verification` field with `verified_at`; the **lifecycle status is not touched** unless you pass `--mark`, which moves `not_reproduced` → `false_positive` and `confirmed` → `confirmed` through the same audited path as `finding mark`. `--no-write` verifies without storing; `--fail-if <verdict,…>` exits `4`; `--timeout` (default `2m` per finding) and `--rate-limit` bound the work.

`finding mark` and `finding verify` write, so `--glob-db`, a `.jsonl` `--db` and `--read-only` all refuse them (exit `2`). A standalone `.sqlite` works with `-S --db <file>`.

### Endpoint and parameter inventory: `endpoints`, `params`

Added in v0.5.3. Both aggregate **stored traffic** — they send nothing, and never read bodies for the aggregate.

```bash
# One row per origin + path template: methods, record counts, params, status mix, findings
vigolium endpoints
vigolium endpoints --host api.example.com -j
vigolium endpoints --source jstangle --sort findings
vigolium endpoints --scan-uuid <uuid> --min-records 2
vigolium endpoints --collapse 5 -n 0

# One row per endpoint + location + name, with a value-type histogram
vigolium params --host api.example.com
vigolium params --type integer,uuid,sequential_id -j     # IDOR candidates
vigolium params --endpoint <endpoint-id> --show-values
vigolium params --location query,json --min-occurrences 3
```

`endpoints` groups paths by **structural template**: `/users/42` and `/users/7` become `/users/{int}`, while `/users/me` and `/about` stay distinct. `--collapse N` additionally merges N or more sibling literal segments sharing the same child shape (blog slugs) into `{var}`; it is **off by default** because it can merge genuinely different routes.

`params` reports one row per endpoint, location and name, with occurrence and distinct-value counts and a histogram of value types (`integer`, `uuid`, `email`, `jwt`, …) over at most 200 values per parameter. Dynamic path segments are parameters too (location `path`, named `{kind}@index`). **Sample values are redacted by default** for cookies, headers and secret-looking names (`token`, `session`, `key`, …); `--show-values` prints them.

Both take `traffic`'s own filters — `--host`, `--path`, `--method`, `--status`, `--source`, `--remark`, `--scan-uuid`, `--from`/`--to` — so `endpoints --host x --status 200` aggregates exactly the records `traffic --host x --status 200` lists. The endpoint ids `params --endpoint` accepts are the ones `endpoints` prints.

<Note>
  `vigolium params --type integer,uuid,sequential_id` is the fastest route to an IDOR shortlist: it finds every parameter whose values look like object identifiers, across everything the scan has ever seen, without sending a request.
</Note>

### Host facts: `fingerprint`, `hosts`, `dns`

Added in **v0.5.5**. `endpoints` and `params` describe what a run *sent*; these three describe what the target *is*, keyed on `host:port` and stored in `host_observations` so later runs and later commands can read them back.

```bash
# Ask each origin what it is, and store the answer
vigolium fingerprint https://app.example -j
vigolium fingerprint -T hosts.txt --depth light -j --compact
vigolium fingerprint -t https://app.example --depth full

# Resolve names into the same store (resolution only — no zone transfer, no brute force)
vigolium dns example.com api.example.com -j
vigolium dns -T hosts.txt --type a,cname --format tsv
vigolium dns example.com --type mx,txt --resolver 1.1.1.1

# Read the facts back — never sends a request
vigolium hosts -j --compact
vigolium hosts '*.example.com' --format tsv --fields hostname,port,title,server,favicon_mmh3
vigolium hosts --has tls --sans            # certificate SANs, one per line: a ready -T list
vigolium hosts --soft-404 -j               # origins answering 2xx/3xx to a path that does not exist
```

**`vigolium fingerprint`** reads each origin's base page (title, server, stack, security headers, JS framework, login forms), its favicon, well-known paths, API-definition paths, GraphQL introspection, a CORS preflight, `OPTIONS`, Host-header variants, and **three random paths to establish the not-found baseline**. It sends **reads only** — GET, OPTIONS, and one GraphQL introspection POST — and does not follow redirects.

| `--depth` | Reads per origin | What it adds |
|---|---:|---|
| `light` | ~9 | Base page, favicon, the not-found baseline |
| `standard` *(default)* | ~60 | Well-known and API-definition paths, GraphQL, CORS, `OPTIONS`, Host variants |
| `full` | more | Sensitive paths, `OPTIONS` on every path that answered, source maps |

The default is `standard` for up to 50 targets and `light` beyond that, so a large `-T` list does not quietly become a 60×N request burst.

<Note>
  **Every fingerprint request goes through the scan engine**, not around it: scope admission, `--rate-limit`, `--max-per-host`, `--max-requests` and WAF pacing all apply, and each request is stored as an `http_record` with `source: fingerprint`. It is also a scan phase — `vigolium run fingerprint` (where the flag is spelled `--fingerprint-depth`), and `fingerprint` in `--only` / `--skip`.
</Note>

**`vigolium dns`** resolves each name — positional, `-t`, or one per line in `-T` — against the system resolver or `--resolver`, and stores the answers as host facts. `--type` picks the record types (`a`, `aaaa`, `cname`, `mx`, `ns`, `txt`, `soa`, `caa`; default all). A URL is reduced to its hostname. **Names outside the configured host scope are refused** unless `--ignore-scope`, and `--no-store` prints without writing. The `dig` and `host` [shims](#tool-shims) route here.

**`vigolium hosts`** lists the latest observation per `host:port` — DNS answers, the TLS handshake and leaf certificate, the fingerprint report, the not-found baseline. `--history` gives every run's instead of the latest. `--has dns|fingerprint|not-found|tls` filters to rows carrying a given fact, `--scan-uuid` to one run's. DNS-only rows carry **port `0`**.

Two outputs are shaped for piping rather than reading:

- **`--sans`** prints the distinct DNS names from the matched certificates' SANs, one per line, and nothing else — feed it straight back as a `-T` file.
- **`--soft-404`** selects origins that answer `2xx`/`3xx` to a path that does not exist. These are the hosts where a status-code-only discovery result means nothing, so it is worth knowing before you read one.

`favicon_mmh3` is the **mmh3 hash in Shodan/FOFA's format**, so a hash you find here is a query you can paste into either; MD5 (Censys) and SHA-256 are stored alongside it.

<Note>
  The not-found baseline is what `traffic --exclude-not-found` and `--fields matches_not_found` judge against. Fingerprint an origin first and a later `traffic` read can drop its soft-404 pages — which a status filter cannot, because they are `200`s.
</Note>

### What each search flag actually searches

Since **v0.4.7** the three text filters cover three different regions, and the difference is load-bearing:

| Flag | Searches | Use it when |
|---|---|---|
| `--header` | **only** the header block of the request/response | you mean a header. `--header password` no longer matches a response body that happens to contain the word |
| `--body` | **only** the request/response body | you mean body content, not a header name that resembles it |
| `--search` | the whole exchange — URL, path, and the raw request/response | the location does not matter |

The region split happens in SQL, so `total` and pagination agree with the rows you get back rather than with a wider match set. The same applies to `--exclude-header` / `--exclude-body`.

<Warning>
  **Search terms are matched literally.** `%` and `_` used to reach SQLite's `LIKE` unescaped and be interpreted as wildcards, so `--body '%'` returned every record and `--body 'api_key'` also matched `api-key` and `api.key`. Every substring filter now escapes the term and carries an `ESCAPE` clause.

  `--host` and `--path` are the deliberate exceptions: they stay **patterns**, where `*` is the wildcard.
</Warning>

**Selecting an exact URL.** `--url` (on `traffic` and `db ls`) selects records whose stored URL matches **exactly**. It is repeatable and OR-ed, and applied *before* pagination, so a match can never be hidden by `-n/--limit`. There is no normalization or case folding — a trailing slash or a different query-parameter order is a different URL. For substring matching use `--path` or `--search`; for identity use `--uuid`.

```bash
vigolium traffic --url 'https://api.example.com/v1/me'
vigolium db ls --url 'https://a.example/x' --url 'https://a.example/y' -j
```

### Extracting one message: `traffic body` / `traffic headers`

Read one side of one stored exchange, without re-sending anything (that is `vigolium replay`). Both take exactly one `--uuid` and one side — `--response` (the default) or `--request` — and always open the source read-only.

```bash
# Save a response body to a file (atomic write, exact bytes)
vigolium traffic body --uuid <uuid> -o response.json

# Pipe it instead
vigolium traffic body --uuid <uuid> | jq .

# Just the receipt: size, sha256, completeness — no body in the output
vigolium traffic body --uuid <uuid> -j

# The request side, and the captured bytes with no decoding
vigolium traffic body --uuid <uuid> --request -o request.txt
vigolium traffic body --uuid <uuid> --representation stored -o body.gz

# Headers as an ordered array — duplicates and ordering survive
vigolium traffic headers --uuid <uuid> -j
vigolium traffic headers --uuid <uuid> --name set-cookie -j
```

- **`--representation`** defaults to `decoded` (supported content encodings removed); `stored` returns the bytes exactly as captured. A body whose decode would be partial fails with `body_incomplete` rather than writing a prefix — pass `--allow-incomplete` to write it anyway, and the receipt keeps `complete: false`.
- **`traffic headers` returns an ordered array**, not a map. A map loses the ordering that distinguishes a proxy-prepended header from an origin one, and collapses three `Set-Cookie` headers into one. `--name` matches case-insensitively and returns **every** matching entry, with `present: true|false` in the receipt.
- **A zero-length body that was captured succeeds**, with `empty: true`. That is a different answer from `body_unavailable`, which means the side was never captured at all — the two used to be the same empty file.
- Printing a binary body to a terminal is refused (write it with `-o`, pipe it, or pass `--force`).

The [error codes](#error-codes-under-j) `record_not_found`, `body_unavailable`, `body_decode_failed` and `body_incomplete` distinguish the four failure states.

### Saving a `-j` result to a file

`traffic`, `finding` and `db ls` accept `-o <path>` alongside `-j`. The result document goes to the file — byte-identical to what the same command prints without `-o` — and a receipt takes its place on stdout:

```bash
vigolium finding -j -n 500 -o findings.json
vigolium traffic -j --compact -n 1000 -o traffic.json
```

```json
{ "artifact": "json_result", "output": "findings.json", "bytes": 66104,
  "sha256": "…", "schema_version": 2, "complete": true }
```

`complete: false` means the file holds **one page** — raise `-n/--limit` (or `-a/--all` on `traffic`) for the whole set. `-o -` forces the document back to stdout. The receipt never contains the document; a caller who wants both can ask twice. For a rendered report or a bulk dump, `vigolium export -o <path> --format <fmt>` is still the right command.

**Counting instead of listing.** `traffic --group-by <field>` counts the matched records by one field rather than printing them: `host`, `method`, `status_code`, `response_content_type`, `source`, `scan_uuid`, `ip`, or `is_authenticated`. An unknown name is a usage error (exit `2`) that lists the valid set. `--group-limit <n>` bounds the buckets, largest first (default `20`, `0` = every bucket); the tail is reported as a count, never dropped.

It **runs the same filters the listing would**, so the buckets describe exactly the rows `traffic` would have shown - the answer to "how many records share this value" without paying for the records. Under `-j`, `items` is the bucket list (`{value, count}`), `total` is the number of buckets, and `total_records` / `other_groups` / `other_records` state what was counted and what the limit left out. It cannot be combined with a flag that renders records (`--raw`, `--burp`, `--markdown`, `--tree`, `--replay`, the `--save-to-*` pair): one counts, the other prints.

**Source, risk & remark filters.** `--finding-source` (on `finding` and `db list`) filters findings by where they came from — `dynamic-assessment`, `spa`, `agent`, `oast`, `source-tools`, or `extension`. On `db list`, `--min-risk <n>` keeps only records whose risk score is at or above `n`, and `--remark <text>` matches text in a record's remarks.

```bash
vigolium finding --finding-source agent          # only findings an agent run produced
vigolium finding --finding-source oast           # only out-of-band callback confirmations
vigolium db ls --min-risk 70                     # high-risk records first
vigolium db ls --remark 'admin panel'
```

**Which database am I looking at?** `db stats` names its source: the human view prints a `Source:` line under `Driver:`, and `db stats -j` fills `items.database.path` (the file actually opened) and `items.database.size` (its bytes, **including the `-wal`/`-shm` siblings** — on a WAL store the main file alone can be a fraction of what the store occupies). Both fields were declared and never filled before v0.4.7, so every `db stats -j` reported `"path": "", "size": 0` for a database it had open. Note that `items` here is an **object**, not a row array, so `total`/`offset`/`limit` describe the one report.

### Surface score vs risk score

`db ls --min-surface <n>` keeps only records whose **attack-surface** score is at or above `n`, and `surface_score` is a `--sort` key on both `db ls` (which also gains a `SURFACE` column) and `traffic`. It is a different question from `--min-risk`, so filtering on the wrong one quietly gives you the wrong shortlist:

| | `--min-surface` (`surface_score`) | `--min-risk` (`risk_score`) |
|---|---|---|
| Asks | "is this record *worth attacking*?" | "is this record *unusual*?" |
| Computed from | the record itself - the percentage of a 17-signal set present: input carried or advertised, method, uploads, the host's tech stack, legacy handlers, a session, a login boundary, a non-standard port, response shape, and origin posture (dynamic, permissive CORS, leaked internals, API markers) | a rank-within-batch percentile against whichever records were flushed alongside it |
| Reproducible | **yes** - same record, same score, every scan | no - depends on the batch |
| Reads back as | percent of surface signals present | a relative percentile |

```bash
vigolium db ls --min-surface 50 --sort surface_score -n 20
vigolium traffic --source probe --sort surface_score -n 50
```

<Warning>
  **Treat the number as a percentage, not a signal count.** The signal set grows between releases and the scale rescales with it, so a threshold ports across versions but "N of M signals" does not. **Scores written before v0.4.6 are not comparable to new ones** - the scale changed from ten points per signal to a percentage of the set.

  A bare host sweep (`run probe`) only ever observes a GET with no session, so the signals that need a request *you* shaped cannot fire. Probe scores top out well under 100 - compare them against each other, not against a full scan's.
</Warning>

**Interactive TUI.** `finding`, `traffic`, `log ls`, `project list`, and `agent session` all take `--tui` to open an interactive browser (arrow keys navigate, enter opens details, `c` copies the id). `--no-tui` forces it off — an escape hatch for scripts, in case the TUI ever becomes the default for a command.

**Importing findings.** `vigolium finding load` ingests findings from JSON, JSONL, or markdown-wrapped agent output, auto-detecting the shape (an agent `{"findings": [...]}` envelope, a single finding object, `ResultEvent` JSONL, or raw database findings). It reads a positional path, `--finding-file <path>`, or stdin, and `--scan-uuid` associates the import with a scan:

```bash
vigolium finding load findings.jsonl
vigolium agent query --prompt-template review | vigolium finding load
vigolium finding load --finding-file agent-output.json --scan-uuid 6f1c2b90-8b1e-4a6c-9d2f-5c7a1e3b9d40
```

**Live proxy bridge.** With a running Burp Suite or Caido exposing the loopback bridge (default listener `http://127.0.0.1:9009`, from the [`burp-vigolium`](https://github.com/vigolium/burp-vigolium) extension or the [`caido-vigolium`](https://github.com/vigolium/caido-vigolium) plugin; env fallback `VIGOLIUM_BURP_BRIDGE_URL`), `vigolium traffic --burp-bridge-url <url>` merges the proxy's live history into the traffic view. `-B` and `--caido-bridge-url` are the same flag, and live rows are labelled with the vendor that answered (`source: burp` / `source: caido`), so `--source caido` selects exactly the traffic Caido served. Add `--save-to-vigolium-db` to persist those bridge rows into the DB (the current page, or every match with `--all`), or `--save-to-burp` to copy DB traffic **into** Burp's Target Site map (the two `--save-to-*` flags are mutually exclusive). See [Using Vigolium with Burp Suite](/getting-started/burp-suite) for bridge setup.

**Push findings to Burp.** `vigolium finding --push-to-burp` (paired with `--burp-bridge-url`) hands the selected finding(s)' evidence request+response to Burp's Organizer — severity-coloured, one item per finding — for manual confirmation. `--to-repeater` opens the finding's request in a Repeater tab (Burp caps Repeater at ~30 tabs/min, so prefer `--push-to-burp` for a large selection), and `--send-via-burp` re-issues the request through Burp's engine to capture a fresh response (with `--http-mode auto|http1|http2|http2_ignore_alpn`). These honour the usual `finding` selectors (`--severity`, `--min-severity`, a fuzzy term, `--id`).

Since **v0.4.5**, `--push-to-burp` and `--to-repeater` are independent destinations that **compose** — one invocation can file a finding in the Organizer *and* open it in Repeater, exactly as `replay --to-organizer --to-repeater` already did. They used to be mutually exclusive here and composable on `replay`: the same operation with two different rules.

```bash
vigolium finding --id 42 --push-to-burp --to-repeater -B http://127.0.0.1:9009
```

```bash
# Push all XSS findings' evidence into Burp's Organizer for manual confirmation
vigolium finding xss --push-to-burp --burp-bridge-url http://127.0.0.1:9009

# Open one finding in a Repeater tab and re-issue it through Burp for a fresh response
vigolium finding --id 42 --to-repeater --send-via-burp \
                 --burp-bridge-url http://127.0.0.1:9009
```

**Cleanup safety.** A bare `vigolium db clean` with no selector is **rejected** — narrow the delete with a filter (`--scan-uuid`, `--host`, `--before`, `--status`, `--severity`, `--search`, `--orphans`, `--findings-only`, `--table`), use `db clean --all --force` to empty the data tables, or `vigolium db reset --force` to delete and recreate the SQLite database file from scratch (it VACUUMs automatically; without `--force` on a TTY it prompts for interactive confirmation).

**Shrinking without deleting: `db compact`.** Added in v0.5.3, for the case where the store is too big but every record still matters as evidence.

```bash
vigolium db compact --db traffic.sqlite --dry-run
vigolium db compact --db traffic.sqlite --older-than 30d --force
vigolium db compact --db traffic.sqlite --max-db-size 2g \
    --skip-content-type '*javascript*' --skip-path '*.js' --force -j
```

It replaces each stored request or response body larger than `--body-over` with its first `--keep-head` bytes. **The record stays**: URL, method, status, headers, content type, content length, hashes and timing are untouched, and `http_records.body_compaction` records the original body length and SHA-256 so you can still prove what was there. Nothing is deleted, and a body already compacted is never compacted again — repeating a pass is a no-op.

Select what to compact with `--older-than`, `--skip-content-type` / `--only-content-type` (globs over the response media type) and `--skip-path` / `--only-path` (globs over the URL path); **a skip glob always wins**. With `--max-db-size` the pass compacts the oldest records first and stops once the database would be at or under that size after `VACUUM`. Sizes take a plain byte count or a `k`/`m`/`g` suffix (binary: `64k` = 65536). SQLite only. A real pass asks for confirmation on a terminal and needs `--force` otherwise; `--dry-run` never does.

### Several export formats in one run

`vigolium export --format` takes a comma-separated list — `html`, `report`, `pdf`, `jsonl`, `markdown` (alias `md`), `sarif`, `bundle` (alias `gz`), `fs` (alias `file-system`). The database is read **once** and every format renders from that one result set, so three formats cost one query rather than three:

```bash
vigolium export --format html,markdown,bundle -o acme-q3
# → acme-q3.html
#   acme-q3.md
#   acme-q3.tar.gz
```

- **One format keeps `-o` verbatim.** `--format html -o report` writes exactly `report`; extension-deriving only kicks in from the second format onward. Because one `-o` cannot name three files, it becomes **required as a base path** as soon as you pass a second format. An extension already on the base is replaced, not stacked.
- **`{ts}` and `{project-uuid}` expand once for the whole run**, before per-format derivation, so every file carries the same timestamp even when a slow renderer (`pdf` shells out to headless Chrome) finishes seconds after its siblings.
- **A failing format does not discard its siblings.** The error is reported inline, the run continues, and the command exits non-zero with an `N of M formats failed` summary. A single format still returns its bare error unchanged.

The same applies to a `gs://` base — each format is uploaded under its own key. `vigolium db export -f` remains single-valued.

### Import

Pull external scan data back into a database. The input type is auto-detected from the path.

```bash
# JSONL export (http_record + finding envelopes, e.g. from `vigolium export --format jsonl`)
vigolium import full-export.jsonl

# Audit output folder (contains audit-state.json + findings-draft/)
vigolium import ./audit-output/

# Merge another vigolium SQLite scan DB into your default database
vigolium import other-vigolium-scan.sqlite

# Merge into an explicit destination (--db is the target)
vigolium import --db team.sqlite other-vigolium-scan.sqlite

# Combine many standalone scan DBs into one (idempotent — re-runs are no-ops)
for f in scans/*.sqlite; do vigolium import --db combined.sqlite "$f"; done

# Compressed archive (.tar.gz / .tgz / .zip) or a cloud-storage object
vigolium import ./scan-bundle.tar.gz
vigolium import gs://<project-uuid>/imports/scan.tar.gz

# One-shot persist of a running Burp Suite's live Proxy history into the DB.
# A filter is REQUIRED — see the warning below.
vigolium import --burp-bridge-url http://127.0.0.1:9009 --host acme.test

# Deliberate whole-history import, unattended
vigolium import --burp-bridge-url http://127.0.0.1:9009 --all-hosts --yes
```

`--burp-bridge-url <url>` (alias `--caido-bridge-url`) turns `import` into a one-shot persist of a running Burp's or Caido's live proxy history into the database (default listener `http://127.0.0.1:9009`; env fallback `VIGOLIUM_BURP_BRIDGE_URL`). It's an import *source*, so it cannot be combined with path arguments or `--glob-db`. Persisted rows keep the vendor they came from (`source=burp` / `source=caido`) and remain available after the proxy stops. See [Using Vigolium with Burp Suite](/getting-started/burp-suite) or [with Caido](/getting-started/caido-plugin).

<Warning>
  **An unfiltered `import -B` is refused (exit 2) since v0.4.5.** Without a narrowing filter it used to copy **every host the operator had ever browsed — carrying those hosts' cookies and tokens** — into the destination database. Where that database is shared with an autonomous agent, that is a cross-engagement leak with nothing in front of it: banking sessions, internal tools, an unrelated client's work.

  It now accepts the same filter set `traffic -B` has, spelled the same way: `--host` (wildcards), `--path`, `--method`, `--status`, `--search`, `--exclude-search`, `--from`/`--to`, `-n/--limit`. Pass `--all-hosts` to opt into the unfiltered form on purpose. A pre-flight prints how many records are about to cross **before anything is written** and asks for confirmation on a TTY; `--yes` skips the confirmation, never the refusal.
</Warning>

Import is **idempotent** either way — new requests are inserted, changed responses refresh the existing row, unchanged traffic is skipped — so re-running it during an engagement is safe.

**Report metadata.** When `import` / `export` render an HTML report, three flags fill in header fields the source data can't supply: `--report-url <url>` sets the target of the report's "Raw Report URL" button (overriding `VIGOLIUM_REPORT_SHARED_URL`; also available on `scan` / `run`), `--report-duration "10h42m5s"` states the scan duration, and `--report-generated-at 2026-08-01T03:00:00Z` stamps the generation time. `import --upload` pushes the artifact to cloud storage, with `--upload-key` overriding the default `imports/<basename>-<ts>.<ext>` object key.

A **SQLite database input** (detected by its magic header, any extension) is a lossless, idempotent SQLite→SQLite merge: HTTP records, findings, scans, agentic scans, OAST interactions, and projects are deduped on their natural keys, and each row keeps its original project. Re-importing the same database adds nothing the second time. The destination is the `--db` target (or the configured default database when `--db` is omitted). Add `-j/--json` to print a per-table merge summary (rows inserted vs. skipped). This pairs with `scan -S --format sqlite`: fan out per-host `.sqlite` files, then merge them back into one queryable DB.

## Replay

Re-send stored traffic — verbatim, or with an exact-byte override — to confirm a finding or push a whole corpus back through a proxy. For payload / insertion-point fuzzing, reach for [`vigolium fuzz`](#fuzz) instead (`replay`'s `-m/--mutate` was removed). The banner is suppressed so bulk output stays pipe-clean.

```bash
# Re-send a stored record and diff the fresh response against the baseline
vigolium replay --record-uuid abc12345

# Re-fire the exact request behind a finding (human-readable summary)
vigolium replay --finding-id 42 --pretty

# Send exact bytes verbatim — a hand-edited raw request overrides the resolved baseline
vigolium replay --record-uuid abc12345 --raw-request-file exact.txt

# Replay a curl command verbatim (auto-baseline by re-sending)
vigolium replay -i "curl -X POST https://example.com/api/login -d 'u=admin'"

# Multi-step auth via a persistent cookie jar
vigolium replay --session-id login -i curl-login.sh
vigolium replay --session-id login --record-uuid <action-uuid>
vigolium replay --record-uuid <uuid> --no-cookies   # send with no cookies (overrides --session-id)

# Confirm against a different environment than the baseline
vigolium replay --record-uuid abc12345 --target https://staging.example.com \
                 -H 'X-Forwarded-For: 127.0.0.1'

# Merge headers from a saved auth session (from `vigolium auth list`)
vigolium replay --record-uuid abc12345 --target https://staging.example.com \
                 --auth-session my-session

# Save a replayed request + its fresh response back into Burp's Target Site map
vigolium replay --record-uuid abc12345 \
                 --burp-bridge-url http://127.0.0.1:9009 --save-to-burp

# Send the exact bytes through Burp's OWN HTTP engine (not Go's client) — force HTTP/1 for desync
vigolium replay -i req.txt --burp-bridge-url http://127.0.0.1:9009 \
                 --send-via-burp --http-mode http1

# Stage the request in a Burp Repeater tab, or store request+response in the Organizer
vigolium replay --record-uuid abc12345 --burp-bridge-url http://127.0.0.1:9009 --to-repeater
vigolium replay --record-uuid abc12345 --burp-bridge-url http://127.0.0.1:9009 \
                 --to-organizer --notes 'IDOR candidate' --highlight orange
```

**Exact-byte override.** `--raw-request <string>` sends those exact bytes instead of the resolved baseline — for a hand-crafted smuggling prefix, a deliberate `Content-Length`, or an unusual method; `--raw-request-file <path>` reads the same from a file (the two are mutually exclusive). `-i/--input` (curl / raw HTTP / Burp) likewise replaces the whole request. For wordlist-scale payload injection at an exact position, use [`vigolium fuzz`](#fuzz).

`--save-to-burp` (paired with `--burp-bridge-url`) adds each replayed request and its fresh response straight into Burp's Target Site map — without proxying it twice — so a confirmed exploit lands back in Burp for manual follow-up (default listener `http://127.0.0.1:9009`; env fallback `VIGOLIUM_BURP_BRIDGE_URL`). See [Using Vigolium with Burp Suite](/getting-started/burp-suite).

**Send through Burp's engine.** `--send-via-burp` routes the send through Burp's own HTTP stack so the exact bytes reach the wire — a deliberate `Content-Length`, a smuggling prefix, or an unusual method is preserved instead of being normalised by Go's client. Pick the wire protocol with `--http-mode auto|http1|http2|http2_ignore_alpn` (default `auto`; use `http1` for request smuggling / desync so `auto` doesn't renegotiate HTTP/2 and reframe the request). Independently, `--to-repeater` (with `--repeater-tab <name>`, default `vigolium`) stages the request in a Burp Repeater tab, and `--to-organizer` (with `--notes` and `--highlight`) stores the request + response pair in Burp's Organizer. All require `--burp-bridge-url`; without them the send path is unchanged. See [Send traffic through Burp's engine](/getting-started/burp-suite#send-traffic-through-burps-engine). Against [Caido](/getting-started/caido-plugin#send-traffic-through-caidos-engine) the same flags apply, mapped to the closest equivalent: `--to-repeater` opens a **Replay session**, `--to-organizer` stores the pair in a named **Replay collection**, and the raw send is always HTTP/1.1.

### Bulk replay

A positional `vigolium replay <term>` does a broad fuzzy match over stored traffic (URL, path, host, method, content-type, source, and the raw request/response) — exactly like `vigolium traffic <term>` — and switches replay into "iterate **every matching stored record**" mode. Passing `--all` or any selector flag does the same. Each matched record is re-sent verbatim through the diff engine, streaming one JSONL object per record with per-record error isolation.

```bash
# Replay every stored request whose text matches "admin" through a proxy (5 at a time)
vigolium replay admin --proxy http://127.0.0.1:8080 -c 5

# Replay ALL stored traffic through a proxy (JSONL out)
vigolium replay --all --proxy http://127.0.0.1:8080 -c 5

# Traffic-style selectors: POST records containing "token" but not "logout"
vigolium replay --host api.example.com --method POST --search token \
                 --exclude-search logout --proxy http://127.0.0.1:8080 -c 5

# Date range + ordering: JSON 200s since a date, oldest-sent first
vigolium replay --status 200 --body 'application/json' --from 2026-07-21 \
                 --sort sent_at --asc -c 5

# Replay every record from a standalone export (project scoping off)
vigolium replay -S --db scan.sqlite --all --proxy http://127.0.0.1:8080 -c 5
```

The selection surface mirrors `vigolium traffic`:

- **Match:** a positional term, repeatable `--search` (AND-combined; matches URL/path **and** the raw request/response), `--host`, `--method` (repeatable), `--status` (repeatable), `--path`, `--source`, `--body`.
- **Exclude:** repeatable `--exclude-search` and `--exclude-body` drop matching records.
- **Range & order:** `--from` / `--to` (see [Date filtering](#date-filtering) for the accepted forms), `--sort uuid|created_at|sent_at|method|status|time` (default `created_at`), `--asc` (default: newest-first), `--offset <n>` for pagination.
- `--all` lifts the default `-n/--limit` cap (100); narrow the set with the selectors instead. Each record is re-sent verbatim — payload / insertion-point fuzzing lives in [`vigolium fuzz`](#fuzz).
- Throttle with `-c/--concurrency` (default 10); cap the set with `-n/--limit` (default 100, lifted by `--all`).
- Combine with `--proxy`, `--save-to-burp`, or `--send-via-burp` as with single-record replay.
- `-S/--stateless --db <file>` reads baselines from a standalone `.sqlite`/`.jsonl` export with project scoping off — it never writes to your project DB.

### Replay through a real browser

`--with-browser` loads each matched record's URL in a real browser routed through `--proxy`, instead of re-sending the stored bytes. Use it when an intercepting proxy needs genuine browser traffic — real TLS fingerprint, JS execution, and subresource loads — rather than a replayed byte stream:

```bash
vigolium replay --host acme.test --all --with-browser --proxy http://127.0.0.1:8080
```

<Warning>
  This is **not** a diff mode. A navigation exposes no status code and no response body, so there is nothing to compare against the baseline. Those runs emit a `browser` object — `requested_url`, `final_url`, `title`, `dialogs`, and `original_method` when the record's method wasn't GET (a navigation can only issue a GET) — and leave `result` **null**, rather than a hollow summary whose zero-valued status would read as a real comparison.
</Warning>

Because nothing is re-sent, `--with-browser` is rejected alongside every flag downstream of the send: `--in-replace`, `--raw-request`, and the Burp send/stage targets. Without `--proxy` it warns — browser traffic isn't being routed anywhere to be captured.

## Date filtering

`--from` / `--to` (aliases `--since` / `--until`) are available on `finding`, `traffic`, `db ls`, `db export`, and `replay`, all sharing one parser. `db clean --before` and swarm's `--records-from since=|until=` accept the same forms:

| Form | Examples |
|---|---|
| Relative offset | `2d`, `12h`, `30m`, `1w`, compound `1h30m`, optional trailing `ago` |
| Named | `today`, `yesterday`, `now` |
| Date | `YYYY-MM-DD` |
| Date + wall-clock time | `YYYY-MM-DD HH:MM[:SS]` |
| Absolute | RFC3339 |

```bash
vigolium finding --since 2d --min-severity high     # last two days
vigolium traffic --from today                       # since local midnight
vigolium traffic --from 2026-08-01 --to 2026-08-01  # the whole of Aug 1
vigolium db ls --since '1h30m ago'
```

Two behaviours are worth knowing. Bare dates and wall-clock times resolve in your **local** zone — resolving them as UTC would silently drop the first hours of the local day, and `--since today` is the flag's whole point. And a bare date on an **upper** bound snaps to end-of-day, so `--from D --to D` is the full day D rather than an empty range. An inverted range is a hard error, not silently-empty output.

<Note>
  `db clean --before` deliberately does *not* snap to end-of-day, so the named day survives the delete.
</Note>

## Fuzz

`vigolium fuzz` injects a caller-supplied payload set into chosen positions of **one** request and streams per-payload response signals (status, size, words, lines, time, reflection, baseline-delta) with match/exclude gating and auto-calibration against the target's catch-all. It is a low-level **primitive**, not a scanner: it sends exactly the payloads you give it at exactly the positions you pick and makes **no vulnerability decision** — it emits raw signals, not findings. The intelligence comes from the caller (typically a coding agent). For confirmation-backed detection of known classes, use the module scanner instead: `vigolium scan-request -i req.txt -m xss,sqli -j`.

```bash
# Fuzz a wordlist into a FUZZ marker; keep only 200s
vigolium fuzz 'https://acme.test/api/FUZZ' -w dir-short --match-status-code 200

# Inject a built-in payload class into one parameter; anomalies vs the calibrated baseline
vigolium fuzz 'https://acme.test/item?id=1' --point URL_PARAM:id --class sqli,xss

# Fuzz from a raw request on stdin with inline payloads; drop 404s
cat req.txt | vigolium fuzz -p "' OR 1=1--" -p '<svg/onload=alert(1)>' --exclude-status-code 404

# Fuzz a stored record (by UUID) as the baseline request
vigolium fuzz -u <record-uuid> --fuzz params -w fuzz

# Agent handle: stream JSONL to stderr, print ONE summary object to stdout
vigolium fuzz 'https://acme.test/api?id=FUZZ' -w ~/wordlists/ids.txt -j

# Let the run tell you what's interesting instead of writing matchers
vigolium fuzz 'https://acme.test/api/FUZZ' -w dir-short --anomaly

# Credential pairs in lockstep across two markers
vigolium fuzz 'https://acme.test/login' -X POST -d 'u=FUZZ&p=FUZZ2' \
  --mode pitchfork -w users.txt:FUZZ -w passwords.txt:FUZZ2

# CI/agent gate: exit non-zero (3) if any result matches
vigolium fuzz 'https://acme.test/admin/FUZZ' -w dir-short --match-status-code 200,301 --fail-on-match
```

**Source** (one of): a positional URL (with `-X/--request`, `-H/--header`, and `-d/--data` to build the method, headers, and body), `-i/--input` (curl, raw HTTP, Burp XML, base64, URL, or `-` for stdin; `--input-file` reads that same value from a file), `-u/--record-uuid` (a stored HTTP record), or a request piped on stdin. `-t/--target` overrides the scheme/host/port the request is actually sent to. `-X`, `-H`, and `-d` apply to **every** source, not just a positional URL, and are applied before positions are resolved — so a marker introduced by `-H 'X-Forwarded-For: FUZZ'` is discovered.

**Positions** (what to fuzz): a literal `FUZZ` marker anywhere in the request (request line, path, header, or body) wins if present; otherwise `--fuzz method|path|params|param-name|headers|cookies|all` (default: all discovered insertion points), `--point TYPE:name` (e.g. `URL_PARAM:id`, repeatable), or `--fuzz-header <name>` (repeatable). `--fuzz-header` **injects** a header the request doesn't already carry rather than erroring — `X-Forwarded-For` is interesting precisely because the client never sends it. The marker keyword is configurable with `--keyword`.

**Payloads** (combine freely): `--class` selects a built-in vulnerability class — `xss`, `sqli`, `ssti`, `ssrf`, `lfi`, `path_traversal`, `xxe`, `cmdi`, `open_redirect`, `crlf` (aliases like `traversal`, `rce`, `sql`, `template` accepted); `-w/--wordlist` takes a builtin name (`fuzz`, `dir-short`, `dir-long`, `file-short`, `file-long`) **or** a file path (repeatable); `-p/--payload` adds an inline literal (repeatable).

**Attack modes** (`--mode`). Numbered markers `FUZZ`, `FUZZ2`, `FUZZ3`… become separate positions, and `-w users.txt:FUZZ` binds a wordlist to one of them:

| Mode | Behaviour |
|---|---|
| `sniper` (default) | One position at a time, the others left at their original value |
| `batteringram` | The same payload placed in every position at once |
| `pitchfork` | Lists advance in lockstep — credential *pairs*, bounded by the shortest list |
| `clusterbomb` | Every combination of every list |

Multi-position modes are **marker-only**: an `httpmsg` insertion point is built against the request it was analyzed on, so applying a second would discard the first's edit. Clusterbomb expansion is bounded, so a runaway product is a clear error rather than an out-of-memory kill.

**Matchers & excludes.** Matchers **keep** a response (OR-combined; empty keeps all): `--match-status-code` (accepts `all`), `--match-size`, `--match-words`, `--match-lines`, `--match-regex`, `--match-time` (ms), `--match-time-z`, and `--match-header`. Each has an `--exclude-*` counterpart that **drops** a response. `--match-mode all` requires every category instead of any (likewise `--exclude-mode`).

Numeric flags take a **comparison predicate**, not just exact equality — `N`, `N-M`, `>N`, `>=N`, `<N`, `<=N`, `!N`, comma-separated. Exact equality alone is near-useless for sizes, since a page carrying a timestamp or CSRF token is never byte-identical twice:

```bash
--match-status-code 200,301   --match-size '>1000'    --match-words 50-80
--match-lines '!0'            --match-time '>500'     # bare N on --match-time means >=N
--match-header 'Location: /admin'                     # presence-only: --match-header Location
```

`--match-header` matches response headers — header reflection is the whole signal for open redirect and response splitting. Reflection is likewise reported as `reflected_raw` (verbatim) separately from an escaped echo, with `reflected_in` naming the location (`body`, `header:Location`), because conflating a verbatim echo with an HTML-escaped one hides the difference between "this might execute" and "the app escaped it".

Auto-calibration (on by default) probes the target's wildcard/catch-all and suppresses matches identical to it — suppressed results carry `"calibrated":true`; disable it with `--no-calibrate`.

**Anomaly scoring** (`-a/--anomaly`) is the alternative to writing matchers by hand. Writing a matcher means knowing the interesting size or status up front; instead, each response is scored against the baseline **and** against the run's own population, and the ones that stand out are kept:

```bash
vigolium fuzz 'https://acme.test/api/FUZZ' -w dir-short --anomaly --anomaly-threshold high
```

The population reference is what makes this work on an unknown target — a status change that *every* payload triggers is the endpoint's normal behaviour, not a signal, and only rarity distinguishes those. Signals include a leaked SQL/stack/template error the baseline lacked, a 5xx, a 4xx→2xx flip (auth-bypass-shaped), size and time outliers, a body no other payload produced, a rare status, a changed `Location`/`WWW-Authenticate`, and unencoded reflection. Outliers use **median-absolute-deviation** rather than standard deviation, since a fuzz population is full of outliers by construction and they would inflate a stddev enough to hide themselves.

Every result carries `anomaly_score` and `anomaly_reasons`. `--anomaly-threshold low|medium|high` (or a number) sets the bar; `--anomaly-min-population` (default 12) is how many responses must land before rarity and outlier signals count. With `--anomaly` and no explicit matchers, "interesting" replaces "keep everything" as the gate.

<Note>
  Anomaly scoring reports **where to look**, never a verdict — the primitive stance holds. Confirm a lead with the module scanner: the `-j` summary hands you a ready `scan-request` query for exactly that.
</Note>

**Baseline timing.** `--baseline-samples N` sends the un-fuzzed request N times to measure timing jitter, giving each result a `time_z` (standard deviations above the baseline mean) that `--match-time-z` can gate on. Default is 1, or 3 under `--anomaly`. This is how to express a time-based signal without guessing a per-target millisecond threshold.

**Curl parity.** `fuzz` accepts curl's long-form flags so a request pasted from DevTools works with minimal editing: `--cookie`, `--user`, `--user-agent`, `--referer`, `--data-raw`, `--data-binary`, `--data-urlencode`, `--form`, `--form-string`, `--get`, `--head`, `--insecure`, `--cacert`, `--cert`, `--key`, `--max-redirs`, `--connect-timeout`, `--max-time`, `--compressed`, `--http1.1`, `--http2`, `--resolve`, `--path-as-is`. Long forms **only** — the short spellings are already taken by vigolium meanings (`-u` record UUID, `-i` input, `-w` wordlist, `-c` concurrency). Body assembly is shared with the curl input parser, so `--data-urlencode` and `--form` behave identically whether they arrive as flags or inside a pasted curl command. `--auth-session` / `--session-id` / `--no-cookies` mirror `replay`.

**Dry run.** `--dry-run` resolves positions and payloads and prints the exact bytes each would send, with **zero** network traffic — the pre-flight to run before committing to a wordlist-scale job. `--ignore-scope` overrides the project-scope guard when the target is outside configured scope.

**Output.** Default is JSONL (one object per send) to stdout — matched-only unless `--all-results`; `--pretty` renders a human-readable table, `-o/--output` writes to a file. Under `-j/--json`, the JSONL streams to **stderr** and a single summary object prints to stdout: `{target, sent, matched, calibrated, baseline, top_results (ranked anomalies), query (a ready scan-request confirmation)}` — a handle a coding agent can act on directly. `--fail-on-match` exits `3` when any result matches, for CI/agent gating. Throttle with `-c/--concurrency` (default 10) and `--delay <ms>`; `--timeout` sets the per-request timeout and `--no-redirects` stops following 30x. Honors `HTTP_PROXY`/`HTTPS_PROXY` for Burp inspection.

**Wire protocol (v0.5.5).** `fuzz` multiplexes rather than pinning HTTP/1.1: `--http-version auto` (the default) tries **HTTP/3, then HTTP/2, then HTTP/1.1**, and the protocol it settled on is reported as `pace.protocol`. curl's spellings work as sugar — `--http3` (prefer, fall back), `--http3-only` (require it, fail otherwise), `--http2` (stay on TCP, use HTTP/2 where ALPN selects it), `--http1.1` (force it).

```bash
vigolium fuzz 'https://acme.test/api/FUZZ' -w dir-short --http3        # prefer QUIC, fall back
vigolium fuzz 'https://acme.test/api/FUZZ' -w dir-short --http3-only   # fail if the target has no h3
vigolium fuzz -i req.txt --http1.1 --send-via-burp --http-mode http1   # desync work stays on 1.1
```

<Warning>
  **Pin `--http1.1` for anything framing-sensitive.** Request smuggling, desync and CL/TE work are HTTP/1.1 properties; letting `auto` reframe the request over h2 or h3 silently tests something else. `--send-via-burp --http-mode http1` is the matching pin on the Burp path.

  `--http-version` is `fuzz`'s own flag. Scanner **modules stay on HTTP/1.1** — only `fuzz` and the discovery phase multiplex (discovery pins its choice per origin via `discovery.engine.protocol`).
</Warning>

**Send through Burp's engine.** `--send-via-burp` (with `--burp-bridge-url`) routes every payload through Burp's own HTTP stack so exact bytes hit the wire — the way to fuzz malformed/smuggling requests (pair with `--http-mode http1`); `--matches-to-organizer` pushes each matched request into Burp's Organizer for triage. See [Send traffic through Burp's engine](/getting-started/burp-suite#send-traffic-through-burps-engine).

<Note>
  `replay`'s `-m/--mutate` flag was **removed** — `replay` now re-sends stored traffic (verbatim, or with an exact-byte `--raw-request` override) and confirms, while `fuzz` owns wordlist-scale payload injection at an exact position. (The `pkg/replay` library and the agent's in-process `replay_request` tool still apply mutations.)
</Note>

## Kit (standalone utilities)

`vigolium kit` exposes the scanner's internal primitives as one-shot, **stateless** tools — no database, no project scope, no scan pipeline. Added in v0.4.1. Full guide: [Utility Toolbox](/others/kit).

```bash
# Scan files, dirs, or stdin for leaked credentials
vigolium kit secret-scan config.env .github/
vigolium kit secret-scan -j --min-confidence high src/
cat bundle.js | vigolium kit secret-scan -

# Unminify / unpack a JS bundle (file, URL, or stdin)
vigolium kit js-beautify https://target.example/main.abc.js
vigolium kit js-beautify -j --extract app.min.js
vigolium kit js-beautify --modules ./out app.min.js   # one file per module

# Mint OOB callback URLs, then drain their interactions later
vigolium kit oast new -n 2 --session run.yaml
vigolium kit oast poll --session run.yaml --wait 30s -j
vigolium kit oast poll --session run.yaml --deregister

# Collect known URLs for a domain from public archives
vigolium kit harvest target.example
vigolium kit harvest --source wayback,commoncrawl target.example -j

# Recover a JWT's HMAC signing secret
vigolium kit jwt-crack -w /path/rockyou.txt eyJhbGciOiJIUzI1NiJ9...

# Built-in wordlists and payload sets
vigolium kit wordlist                    # list them
vigolium kit wordlist fuzz > fuzz.txt    # print one
vigolium kit payload --class sqli,xss

# Discover hidden parameters an endpoint accepts, Arjun-style (v0.5.3)
vigolium kit param-mine -t 'https://acme.test/search?q=x'
vigolium kit param-mine -t https://acme.test/api/login -X POST -d 'user=a' -j
vigolium kit param-mine -t https://acme.test/api -X POST \
    -H 'Content-Type: application/json' -d '{"id":1}'
vigolium kit param-mine -t https://acme.test/ -w my-params.txt --max-requests 200

# Collect scratch left in the temp dir by interrupted runs (v0.5.0)
vigolium kit tmp-clean                   # idle for 6h or more
vigolium kit tmp-clean --max-age 0       # everything not currently held
```

`secret-scan --fail-on-match` and `jwt-crack --fail-on-crack` exit `3` on a hit, for CI/agent gating. `js-beautify` never exits non-zero for a *degraded* analysis — read its `status` and `diagnostics` fields, not the exit code.

**`kit param-mine`** finds parameters an endpoint reads although nothing you have sends them — `debug=`, `callback=`, `admin=`. Two baselines with a random parameter profile the endpoint first; candidate names then go out in chunks sized to the transport, each with its own random value, and a chunk whose answer differs (status, header set, body length or content, or an echoed value) is **bisected to single names**. Every surviving candidate is re-sent twice with fresh values and kept only if the difference reproduces, which is what keeps the output short enough to act on.

Names go on the query string for `GET`/`HEAD`/`DELETE` and into the form or JSON body otherwise. The same machinery runs inside a scan as the **`param-mining` phase** — on by default at `--intensity deep`, off below, and forced either way with `--param-mining` / `--param-mining=false`. Its budget is `dynamic-assessment.param_mining` in config. Mined parameters become insertion points, so the injection modules test them too.

## Tool shims

A coding agent reaching for `ffuf`, `nuclei`, `katana`, `gau` or `arjun` will often *find* them on the host — and then the whole run happens outside the pinned database, outside the phase model, invisible to every later `finding`/`traffic`/`replay` call. So Vigolium accepts each tool's own argv and routes it to the native phase, printing the translation before it runs:

```bash
$ vigolium ffuf -u https://target.example/FUZZ -w words.txt
◆ routed to: vigolium run discovery -t https://target.example --discovery-wordlist words.txt
```

| Shim | Routes to |
|---|---|
| `vigolium ffuf -u <url>/FUZZ -w <list>` | `run discovery --discovery-wordlist` |
| `vigolium nuclei -u <url> -severity high -tags cve` | `run known-issue-scan --known-issue-scan-*` |
| `vigolium katana -u <url>` | `run spidering` |
| `vigolium gau <domain>` | `run external-harvest` |
| `vigolium arjun -u <url>` | `fuzz --fuzz param-name --anomaly` |

Mapped flags include the pace knobs (`-t`/`-threads`/`-c` → `--concurrency`, `-rate`/`-rl` → `--rate-limit`), headers, proxy, and each tool's own selectors. Both `-u X` and `-u=X` parse.

- **An unmapped argument is a hard error naming the native command**, never a silent drop — a dropped flag is a scan that ran with a scope nobody chose. `vigolium ffuf --mc 200` tells you to run `vigolium run discovery --help`.
- **Where a concept doesn't exist, the shim says so rather than approximating.** `katana -d 3` errors: Vigolium's spider is a state machine over DOM snapshots, not a depth-limited link follower, so bound it with `--spider-max-time` instead.

The shims are a redirect for muscle memory, not a full port — once you know the native form, prefer it. It takes every Vigolium flag; the shims take a subset.

### Testing an extension without a target

Added in v0.5.3. Two commands close the loop between writing an extension and trusting it in a scan.

**`ext run`** (same as `ext eval --record-uuid`) loads one extension the way a scan does and calls its handlers against one **stored HTTP record**. The record is read-only: `vigolium.db` reads work, while `record.annotate` / `addRemarks` and `vigolium.ingest` return `false`. **Every request the extension makes fails** with `network disabled in ext eval; pass --allow-network` and is counted in `network_calls_blocked`; `--allow-network` sends them for real. `vigolium.oast` and `vigolium.agent` are unavailable.

With no `--handler`, every handler the module's `scanTypes` declare runs; `scanPerInsertionPoint` runs once per insertion point the module accepts, or only on `--insertion TYPE:name` (`URL_PARAM:id`, `BODY_PARAM:user`, `HEADER:X-Api-Key`). Exit `1` when a handler threw — the `errors` list says where.

**`ext test`** runs each extension's fixture cases and checks what it reports. Fixtures live next to the extension:

```
my-ext.js
my-ext.fixtures/basic.http               # raw request, blank line, raw response
my-ext.fixtures/basic.expect.json        # {"findings": 1, "errors": 0}
my-ext.fixtures/basic.responses/*.http   # canned responses for an active extension's requests
```

`expect.json` takes either a count or a list of matchers — `{"findings": [{"name~": "…", "severity": "high", "confidence": "firm"}], "errors": 0}`. A case can carry its expectation inline instead, as a leading `// expect: {...}` comment, alongside `// handler:`, `// insertion:` and `// url:` directives. In a response file, `// match: <text>` serves that response only to a request whose target or body contains the text. `-j` reports one item per case; exit `1` when any case failed.

<Warning>
  **An `--ext` extension that fails to load now stops the scan (v0.5.3).** It exits `2` with `error.code: "extension_load_failed"` **before any request is sent**. `--ext-allow-failures` restores the old behavior of scanning without it.

  `ext lint` also became strict: it loads the file in a side-effect-free full VM, **errors** on missing handlers and exports, caps top-level extension code at 10s, and flags unknown YAML keys with suggestions (`extensions.yaml_strict`). `--strict` promotes warnings; `--stdin-kind js|ts|yaml` lints piped input. Module selection (`-m`, `--module-tag`) now applies to JS/YAML extensions too, on the CLI and over REST.
</Warning>

### `agent query`: single-shot prompts

```bash
vigolium agent query --source ./src --prompt-template security-code-review

vigolium agent query 'review this code for vulnerabilities'

```

### `agent triage`: confirm or retire one finding

```bash
vigolium agent triage 42                      # triage finding id 42
vigolium agent triage 42 --max-duration 10m
vigolium agent triage 42 --no-probe           # decide from captured traffic; contact nothing
vigolium agent triage 42 --no-write           # report the verdict without storing it
vigolium agent triage 42 --dry-run            # render the prompt, don't call the agent or write
vigolium agent triage 42 --show-prompt -v     # print the prompt, show per-tool result previews
```

Picks one stored finding and asks an agent whether it's real. The agent reads the finding's description and captured request/response, may re-probe the live target with its HTTP tool, and writes back a verdict plus reasoning.

| Verdict | What happens |
|---|---|
| `confirmed` | The finding's status moves to `confirmed` |
| `false_positive` | The **status** moves to `false_positive` |
| `inconclusive` | **Nothing is written** — the evidence settled neither way |

<Warning>
  **A `false_positive` verdict now changes the finding's *status*, not its severity (v0.5.3).** It used to downgrade severity to `info`, which both destroyed the original assessment and left the finding in every report and `--fail-on` gate at a lower rank. A dismissed finding is now simply left out of the gate, `scan diff` and `--new-since` by default — and `finding --verdict false_positive` lists exactly what the agent retired. The reasoning is still appended to the description.
</Warning>

`--no-probe` denies the agent its HTTP, browser and shell tools, so it decides from captured traffic alone and returns `inconclusive` when that cannot settle it — use it when the target must not be touched again. `--no-write` (alias `--report-only`) runs the full triage and reports the verdict without storing it. `--max-duration` defaults to `5m` (`0` = no limit); past it the run exits `5`.

Since v0.5.3 `agent triage` and `agent query` each **record their own `agentic_scans` row**, so a triage is visible in `agent session` and `log ls` like any other run.

### `agent swarm`: AI-guided multi-phase scan

```bash
vigolium agent swarm -t https://example.com --discover
vigolium agent swarm -t https://example.com --discover --prompt 'focus on API injection'

# Natural-language positional prompt — preserved as extra instruction context alongside flags
vigolium agent swarm "focus on the checkout and payment flows" -t https://example.com --discover

# Load prose guidance plus raw HTTP request seeds from one plan file
vigolium agent swarm -t https://example.com --plan-file ./pentest-plan.md

# Run browser-based login; describe credentials and roles in the prompt
vigolium agent swarm -t https://example.com --browser-auth \
  --prompt "log in as admin/admin123, then compare the user role"

# Skill control (force-load attack-vector skills, bypass planner selection)
vigolium agent swarm -t https://example.com --discover --skill-tag xss,idor
vigolium agent swarm -t https://example.com --discover --no-skill-filter

# Olium provider/model overrides (same set as `agent autopilot` / `agent query`)
vigolium agent swarm -t https://example.com --discover --provider anthropic-api-key --model claude-opus-4-7
vigolium agent swarm -t https://example.com --discover --base-url http://localhost:11434/v1 --llm-api-key "$KEY"

# Plan from traffic already in the project DB instead of discovering
vigolium agent swarm -t https://example.com --all-records
vigolium agent swarm -t https://example.com \
  --records-from "host=example.com,status=200,method=POST,path=/api,since=2026-07-01"
```

`agent swarm` accepts the olium override flags `--provider`, `--model`, `--base-url`, `--llm-api-key`, `--oauth-cred`, and `--oauth-token`; each falls back to `agent.olium.*`. For the Vertex providers, `--gcp-project` and `--gcp-location` set the GCP project and region (falling back to `$GOOGLE_CLOUD_PROJECT` / `$GOOGLE_CLOUD_LOCATION`, then `agent.olium.google_cloud_*`, then `us-central1`). `--prompt` and the positional `[prompt]` are the same task-guidance slot and stay verbatim when structured target/source flags are also present.

**Choosing the input records.** Without `--discover`, swarm plans from the traffic it's given: `--all-records` uses every HTTP record in the active project, and `--records-from` filters them by a spec string (`host=`, `path=`, `method=`, `status=`, `source=`, `since=`, `until=`, comma-separated — `since`/`until` take the [shared date grammar](#date-filtering)). `--max-plan-records` caps how many reach the plan agent — it selects the most interesting with one slot per URL prefix, and `--intensity` overrides the default (quick `10`, balanced `25`, deep `50`; `0` = no limit).

**Tuning the run.** `--probe-concurrency` (default 10), `--probe-timeout` (default 10s), and `--max-probe-body` (default 2 MB) bound the probing stage; `--sub-agent-concurrency` (default 3) caps parallel source-analysis sub-agents (routes, auth, extensions); `--max-master-retries` (default 3) is how many times a master-agent parse failure is retried. `--disable-guardrail` skips the prompt-safety classifier on the natural-language prompt — use it only when a known-good prompt is being refused.

### `agent autopilot`: autonomous agentic scan

```bash
# Natural-language prompt — target, source, and focus auto-extracted
vigolium agent autopilot "scan VAmPI source at ~/src/VAmPI on localhost:3005"
vigolium agent autopilot "test auth bypass on https://app.example.com"

# Plain target
vigolium agent autopilot -t https://example.com/api

# Source-aware (auto-runs vigolium-audit first to build context)
vigolium agent autopilot -t https://example.com --source ./src
vigolium agent autopilot -t https://example.com --source ./src --audit=off   # disable vigolium-audit

# Pipe a curl command or raw HTTP request via stdin
curl -s https://example.com/api/users | vigolium agent autopilot
cat request.txt | vigolium agent autopilot -t https://example.com

# Pass curl/raw HTTP as input
vigolium agent autopilot --input "curl -X POST -H 'Content-Type: application/json' \
  -d '{\"user\":\"admin\"}' https://example.com/api/login"

# Focus the agent on specific vulnerability classes
vigolium agent autopilot -t https://example.com --prompt "focus on auth bypass and IDOR"

# Skill control — force-load skills by name or tag, or skip pre-flight selection
vigolium agent autopilot -t https://example.com --skill idor-blast-radius
vigolium agent autopilot -t https://example.com --skill-tag xss,idor
vigolium agent autopilot -t https://example.com --no-skill-filter

# Intensity presets — quick (CI/PR), balanced (default), deep (pentest)
vigolium agent autopilot -t https://example.com --intensity deep
vigolium agent autopilot -t https://example.com --source ./src --intensity quick

# Narrow source scope
vigolium agent autopilot -t https://example.com --source ./src \
  --files "routes/api.js,controllers/auth.js" \
  --prompt "Focus on the new payment endpoint"

# PR / diff-aware scan
vigolium agent autopilot -t https://example.com --source ./src --diff "main...feature-branch"
vigolium agent autopilot -t https://example.com --source ./src --last-commits 3

# Backend and authenticated testing (browser is always available)
vigolium agent autopilot -t https://example.com --provider anthropic-api-key
vigolium agent autopilot -t https://example.com \
  --prompt "log in as admin/admin123, then test protected routes"

# Mine existing project/Burp traffic and supply application documentation
vigolium agent autopilot -t https://example.com --prior-context auto
vigolium agent autopilot -t https://example.com \
  --burp-bridge-url http://127.0.0.1:9009 --knowledge-base ./app-docs

# Durable-mode resume and explicit debug artifacts
vigolium agent autopilot --resume <agentic-scan-uuid> \
  --prompt "continue the remaining checks"
vigolium agent autopilot -t https://example.com \
  --session-dir ./debug/run-1 --transcript ./debug/run-1.jsonl

# Limits and previews
vigolium agent autopilot -t https://example.com --intensity deep --max-duration 4h
vigolium agent autopilot -t https://example.com --intensity quick --triage
vigolium agent autopilot -t https://example.com --source ./src --dry-run
vigolium agent autopilot -t https://example.com --source ./src --show-prompt
```

Autopilot and swarm no longer expose CLI flags named `--focus`, `--instruction`, `--instruction-file`, `--browser`, or `--credentials`. Put those details in `--prompt`. The REST agent endpoints keep structured equivalents for API clients.

**Knowledge base.** `--knowledge-base <file|dir>` front-loads operator-supplied docs about the app. Prose (markdown / txt / rst) is LLM-distilled into a compact brief plus a document index, with the full documents left on disk for the agent to read on demand. **HTTP-traffic exports found in the same path — HAR, Burp XML, curl, OpenAPI/Swagger, Postman, URL lists, raw HTTP — are auto-detected, parsed, and ingested into the project database as normal traffic** (`source=knowledge-base`), with a sample folded into the brief. So a knowledge base can seed the agent with real requests, not just prose. `--knowledge-base-no-traffic` turns that off and treats every file as prose; `--knowledge-base-raw` skips the LLM distillation and inlines the deterministic index only (offline / reproducible runs). Both are no-ops without `--knowledge-base`.

**Other autopilot controls.** `--disable-guardrail` skips the prompt-safety classifier on the natural-language prompt (only when a known-good prompt is being refused). `--post-halt-gap-threshold <n>` sets how many new `(method, URL)` routes the post-halt probe must turn up before the agent is re-entered (`0` = the built-in default of 5).

### `agent audit`: unified source audit (vigolium-audit + piolium)

Runs the vigolium-audit harness and/or piolium against a single source tree under one AgenticScan, with per-driver session subdirs and a post-pass findings dedup. `vigolium-audit` is the embedded harness name; the CLI driver value is `audit`.

```bash
# Default driver is "auto": run audit; fall back to piolium only if the
# claude/codex CLI required by audit is missing. Balanced mode.
vigolium agent audit --source .

# Run both drivers back-to-back, unconditionally
vigolium agent audit --driver both --source ./backend

# Single driver — piolium only (no audit, no fallback)
vigolium agent audit --driver piolium --source ./backend --mode lite
vigolium agent audit --driver audit   --source ./backend --agent claude

# Multi-driver, deep intensity, against a remote git URL
vigolium agent audit --driver both --source git@github.com:org/repo.git --intensity deep
vigolium agent audit --driver both --source https://github.com/org/repo.git --commit-depth 0   # full history

# Override pi's provider/model for the piolium leg
vigolium agent audit --driver both --source ./backend \
  --pi-provider vertex-anthropic --pi-model claude-opus-4-6

# Driver-specific modes (piolium=longshot/smoke, audit=mock)
vigolium agent audit --driver piolium --source ./mono-repo --mode longshot \
  --plm-longshot-langs python,go --plm-longshot-limit 200
vigolium agent audit --driver audit --source ./backend --mode mock

# Cap commit-history scan window (piolium only)
vigolium agent audit --driver piolium --source ./backend --plm-scan-since "60 days ago"
vigolium agent audit --driver piolium --source ./backend --plm-scan-limit 500

# Skip post-pass dedup or preflight checks
vigolium agent audit --source ./backend --no-dedup
vigolium agent audit --source ./backend --no-preflight

# Pull source from a cloud-storage archive, upload results when done
vigolium agent audit --source gs://my-bucket/snapshots/repo.tar.gz
vigolium agent audit --source ./backend --upload-results

# Stateless one-shot: run into a throwaway DB and auto-render a self-contained HTML report
vigolium agent audit --source ./backend -S

# Bundle the HTML report + each ran driver's raw vigolium-results/ tree into one folder
vigolium agent audit --driver both --source ./backend -S --output-dir ./audit-bundle
```

On `agent audit`, `--intensity deep` resolves to the `deep,confirm` mode chain (the modes run back-to-back), matching the `POST /api/agent/run/audit` endpoint; `quick` maps to `lite` and `balanced` to `balanced` (both single-mode).

`-S/--stateless` runs the whole audit into a throwaway temp DB (your main DB is untouched, mirroring `scan -S`) and, on completion, renders a self-contained HTML report from the run's findings to `vigolium-result/vigolium-audit-report.html` (override with `-o/--output`, which supports `gs://` and `{ts}`). `--output-dir <dir>` (stateless-only) additionally bundles that report **and** a copy of each ran driver's raw `vigolium-results/` tree into one folder — a single driver lands flat at `<dir>/vigolium-results/`, multiple are namespaced under `<dir>/<driver>/`. `-S` is rejected with `--interactive`. `--keep-raw` is **on by default** for the CLI (it retains the `<source>/vigolium-results/` copy); `--clean-raw` removes that source copy after the run.

**Bring-your-own-key (audit leg).** Three mutually exclusive flags supply credentials for the run without touching your config; each accepts a literal value, `$ENV_NAME`, or `@path`:

```bash
vigolium agent audit --source ./backend --api-key '$ANTHROPIC_API_KEY'
vigolium agent audit --source ./backend --oauth-token @~/.claude/setup-token
vigolium agent audit --source ./backend --agent codex --oauth-cred-file '$CODEX_AUTH'
```

- `--api-key` — API key for the resolved agent (claude → `ANTHROPIC_API_KEY`, codex → `OPENAI_API_KEY`). Empty inherits `agent.olium.*`.
- `--oauth-token` — Anthropic OAuth bearer token, Claude only (produced by `claude setup-token`).
- `--oauth-cred-file` — OAuth credential **file** (Codex `~/.codex/auth.json` shape). For piolium runs it's staged under the pi agent dir with backup-and-restore.

**Run controls.** `--show-thinking` renders the agent's internal thinking blocks in the live stream (off by default — they're verbose). `--preflight-timeout <dur>` bounds the per-driver preflight check (default `30s`, applies to both `pi` and `claude`). The piolium retry knobs are `--plm-phase-retries`, `--plm-command-retries`, and `--plm-longshot-timeout` (per-file kill timer in ms, longshot mode); `0` on any of them means "use piolium's own default".

### `log`: replay an agentic session

Every olium agent run (autopilot, swarm, query, `olium`) writes a Pi-compatible `transcript.jsonl`. Replay it as a rendered conversation, or dump the raw JSONL:

```bash
vigolium log                       # Replay the most recent agentic session
vigolium log <session-id>          # Replay a specific session
vigolium log ls                    # Merged table of native + agentic sessions
vigolium log --raw                 # Print the raw transcript JSONL verbatim instead of the rendered replay
vigolium log --strip-ansi > run.txt   # Strip ANSI colour codes (for piping into a file or another tool)
vigolium log -S --db ./scan.sqlite <uuid>   # Read the session from a standalone export
```

Three v0.4.5 fixes worth knowing:

- **`-S` works.** `log` used to reject it outright with `unknown shorthand flag` — a non-zero exit and no output, i.e. a control that looked live and could only ever report nothing. It now reads through the same path `finding`/`traffic` do, so `$VIGOLIUM_DB_PATH` or `-S --db <file>` reaches that session's database with project scoping off.
- **`--follow` no longer hangs on a dead scan.** Auto-follow used to fire whenever the scan row said `running`, and a scan reaped by a deadline or SIGKILL says that *forever* — so an omitted `--follow` parked the read until the caller's own timeout, on precisely the runs that had already timed out. Now a non-TTY stdout never auto-follows, a row whose log hasn't been written to for ~2 minutes is treated as stale, and an explicit `--follow` / `--follow=false` still wins. `vigolium log <uuid> | cat` terminates promptly.
- **WAF notices survive the tail window.** They fire *early* (the edge is fingerprinted on the first clean response), so the default 200-line tail was structurally the wrong end of the file for the most important thing in it. Any `[waf-block-detected]` / `[waf-pacing-armed]` line above the window is now reprinted above it under an "N earlier notice(s)" header.

<Note>
  For live progress from a **program**, prefer [`--events ndjson`](#machine-event-stream-events-ndjson) on the scan itself — a structured stream rather than a rendered log.
</Note>

## Configuration

```bash
vigolium config ls
vigolium config ls server             # Filter by a key prefix
vigolium config ls '*burp*'           # Filter keys by glob
vigolium config view 'notify.*'       # Print a subtree
vigolium config ls --show-secrets     # Reveal masked secret values (API keys, tokens) in plaintext

# Set individual keys by dotted path — missing nested sections are created automatically
vigolium config set server.enable_burp_bridge true
vigolium config set server.burp_bridge_url http://127.0.0.1:9009
vigolium config set notify.enabled true
vigolium config set notify.provider telegram
vigolium config set notify.severities high,critical      # coerced to a list
vigolium config set notify.telegram.bot_token <bot-token>
vigolium config set notify.telegram.chat_id <chat-id>
vigolium config set database.driver postgres

vigolium config validate          # Check the effective config for anything that breaks or weakens scans
vigolium config clean
vigolium init                     # Initialize ~/.vigolium with defaults
vigolium doctor                   # Diagnose configuration and tool readiness
vigolium auth                     # Authentication management utilities
vigolium project                  # Manage multi-tenant projects
```

`vigolium config ls` (aliases `list` / `view`) redacts sensitive values — API keys, tokens, credentials — as `[redacted]` by default. Pass `--show-secrets` to reveal them in plaintext; it prints a warning to stderr. The generic `-F/--force` no longer reveals secrets (it only skips confirmation prompts). Both accept an optional key prefix or glob (`config ls server`, `config view 'notify.*'`) to print just a subtree.

`vigolium config set <key> <value>` takes a dotted path and **creates missing intermediate sections**, so a previously-unset nested key — `notify.telegram.bot_token`, `server.burp_bridge_url`, `server.enable_burp_bridge` — can be set directly instead of failing with *"key not found"*. The value is coerced to the field's declared type (bool / int / float / comma-separated list), and the key is validated against the config schema so a typo is rejected up front.

Since v0.5.3 `config set` also parses **JSON and YAML list and map values**, validates before writing, and writes **atomically** (as does `scope set`), so an interrupted write cannot leave a half-written config.

<Warning>
  **A broken `--config` exits `1` (v0.5.2).** It used to fall back to the defaults silently, so a typo'd path or a malformed file produced a scan with none of your settings and no indication why.
</Warning>

### `config validate`: catch a config that weakens scans

```bash
vigolium config validate                              # exit 1, error.code config_invalid, on any error
vigolium config validate -j                           # items[] of {key, severity, code, message, fix}
vigolium config validate --project <uuid> --strict    # a project's merged settings; fail on warnings too
```

Added in v0.5.3. It checks the effective configuration — the global file, plus a project's overlay with `--project` — with the same rules `config set` and `scope set` enforce and `doctor`'s Scope check reports:

- Malformed scope patterns, and host patterns carrying a scheme, path or port.
- **An exact-host include that silently drops every subdomain** — the misconfiguration that makes a scan look clean because it never reached anything.
- Invalid status-code patterns, origin modes and body actions.
- OAST settings, each section's own checks, and keys your config file sets that Vigolium does not recognise.

With a database available, a wildcard-free `scope.host.include` is also checked against the targets of the last `--recent` scans. `--strict` fails on warnings as well as errors.
